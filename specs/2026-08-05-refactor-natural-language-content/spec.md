## 背景与目标

自然语言工程内容经过多轮局部修改后，可能同时保留新旧规则、重复表达同一职责、使用漂移术语，或把同一主题拆散在多个章节。普通局部编辑倾向于完成眼前改动，不能稳定保证整体语义和结构仍然一致。

本事项建立一个可选 Skill，用于审计和重构 Spec、Skill、Prompt、规范、评估标准、AGENTS 等自然语言工程内容。Skill 应先依据本次请求和差异执行低成本影响判断，再按风险逐步扩大检查范围；只有用户明确授权整体整理、去重、冲突处理或重构时，才执行超出局部请求范围的改写。

## 非目标

- 不处理普通源代码、测试代码、依赖、锁文件和一般配置的重构；
- 不把每次自然语言局部修改都升级为全文扫描；
- 不自动决定权威来源不明的冲突规则；
- 不把有意重复、摘要或面向不同读者的说明机械删除；
- 不在首版增加专用 Parser、索引器、Validator、Package 或 Adapter；
- 不把一般文章润色、营销文案改写或翻译作为默认范围。

## 用户或调用场景

1. 用户明确要求整体整理一份经过多轮修改的 Spec，消除冲突、重复和术语漂移。
2. Agent 修改自然语言工程内容时观察到公共定义、规范性规则或章节结构的跨范围风险，只读扫描并提示问题，不自动扩大改写范围。
3. 用户只修改错别字、局部表达或普通代码，Skill 不触发全文扫描或重构。
4. 两条规则互相冲突但权威性不明，Skill 保留冲突并请求决策，不静默选择。

## 输出与行为契约

- 区分 `audit` 与 `refactor`：隐式触发只允许只读审计，明确重构意图才允许改写授权范围内内容；
- 依据请求和当前差异执行增量门禁，不为判断风险重新读取全文；
- 将问题区分为冲突、语义重复、术语漂移、结构碎片、引用失效和权威不明；
- 先搜索相关概念、标题、规则 ID 和引用，再决定是否需要全文语义扫描；
- 对事实、程序搜索结果和 Agent 推断分层表达；
- 重构后复查残留引用、术语和规范性规则，并报告未解决问题与实际扫描范围；
- 中文作为 Skill、Reference、Eval 和默认输出的首要语言。

- [x] **AC-001** 新 Skill 有明确的适用对象、负向触发条件、审计/重构授权边界和中文优先约定。

- [x] **AC-006** README、能力地图、问题图谱和成熟度说明能准确发现该 Skill，且不把它写成确定性 Validator。

## 约束

- 技术约束：首版以 Agent 语义判断和现有搜索工具为主，不新增确定性实现。
- 兼容约束：不改变 Specflow、Repository Doctor 和现有 Skill 的职责；确定性结构检查继续由 Harness 承担。
- 权限与安全约束：隐式触发不能扩大写入范围；权威性不明时必须停止自动合并。
- 数据与隐私约束：行为案例只使用自行构造的自然语言材料，不保存 Prompt 或工具原始输入输出。
