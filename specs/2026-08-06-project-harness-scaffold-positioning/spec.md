## 背景与目标

仓库已有“Agent 工程治理骨架”“最小项目级参考闭环”等事实，但“是否可作为通用项目 Harness 化脚手架”需要读者跨 README、能力地图、目标设计和成熟度文档自行推导；同时，“项目级接入内核”与“完整 Agent Runtime 或企业研发平台”的边界没有在入口处集中说明。

本事项将既有稳定定位收敛为直接、可检索、不过度承诺的表述，并在设计文档中明确接入路径、仓库提供项、采用方补齐项和当前成熟度边界。

## 非目标

- 不新增 Harness、Starter、Doctor、Adapter 或运行时能力；
- 不把当前仓库描述成完整 Agent Runtime、企业研发平台或所有领域基础设施的集合；
- 不修改长期 Knowledge 的既有语义，也不引入特定公司的系统、接口或操作手册；
- 不归档事项，不执行 Commit、Push、PR/MR 或发布。

## 用户或调用场景

1. 新读者从 README 判断本仓能否用于通用项目 Harness 化接入。
2. 采用方在目标设计中判断复制 Starter 后还需补齐哪些项目专属能力。
3. 维护者在能力地图和成熟度文档中区分“接入脚手架已有”与“完整运行时尚未提供”。

## 输出与行为契约

- README 使用一句话说明“通用项目级 Agent Harness 化脚手架与参考底座”，并列出仓库直接提供和采用方补齐的边界；
- 能力地图统一把确定性层称为“项目级 Harness 化接入内核”，且不扩大已实现范围；
- 目标仓库设计增加从 Starter 到项目专属集成和验证的接入路径，明确初始化成功不等于 Harness 化完成；
- 成熟度文档将该定位绑定到最小范围 `reference-implemented`，不把局部测试外推为完整运行时成熟度；
- 文档检查失败时保持事项进行中，并在 Validation Report 中记录未通过项。
