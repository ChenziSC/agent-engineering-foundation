# Spec：公开发布来源复核与历史脱敏

## 背景与目标

现有公开策略把逐项仓外覆盖台账设为发布前置，但维护者确认实际不存在该台账；发布清单却把它标为已完成，形成不可验证的治理声明。同时，归档验证报告保存了本机绝对路径，仓外私有词表扫描在当前树和 Git 历史中均能命中。

本事项把发布要求收敛为每个版本都能实际执行的人工来源与权属复核，并在不伪造普通提交证据的前提下清洗绝对路径历史。

## 完成条件

- **AC-001**：根规则、长期 Knowledge、来源说明、能力图谱和发布清单不再声称逐项仓外覆盖台账存在或必需。
- **AC-002**：上述入口一致要求维护者在每次公开发布前复核新增和修改内容的来源、公开处理等级、权属、脱敏结果与排除项。
- **AC-003**：归档报告使用仓库相对路径 `.agents/skills`，当前树和 `main` 历史不再包含原本机绝对路径；只读 PR 引用中的同一低风险历史路径经维护者人工复核并明确接受。
- **AC-004**：历史清洗具有本地备份和可恢复 Bundle；受影响的归档 Receipt 与产物摘要在重写后保持一致。
- **AC-005**：Repository、Specflow、Knowledge、Git 全范围敏感扫描和 `git diff --check` 通过。

## 非目标

- 不要求维护者公开合同、保密协议、内部审批材料或私有来源记录；
- 不降低独立编写、第三方许可、脱敏和人工权属复核要求；
- 不把历史重写授权扩展到仓库可见性切换、Release、Pages 或 Package 发布。
