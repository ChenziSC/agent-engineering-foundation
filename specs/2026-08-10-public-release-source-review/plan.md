# Plan：公开发布来源复核与历史脱敏

## 方案

1. 将“逐项仓外覆盖台账”统一替换为“每个公开版本发布前人工来源与权属复核”，同步根规则、长期 Knowledge、来源说明、能力图谱、发布清单和 Registry 路由词。
2. 先提交当前规则变化，使历史清洗在干净工作树上执行；推送留到最终验证之后。
3. 创建带时间戳的本地备份引用和 Git Bundle，再重写引入绝对路径的历史内容及对应 Receipt 摘要。
4. 重写后重新生成 Knowledge Projection 证据、完成本事项验证与归档，并运行全量仓库、历史和敏感信息检查。
5. 只有最终工作树、Receipt 链和检查全部通过时，才强制推送已授权的 `main`。

## 关键决策

- 私有台账不是 GitHub、Apache License 2.0 或通用开源流程的强制要求；本仓保留可执行的逐版本人工复核，不保留与事实不符的“台账已存在”声明。
- 当前报告属于既有 Receipt 冻结产物，不能用普通后续 Commit 覆盖摘要；脱敏必须在已授权的历史重写中同时修正原内容与对应历史 Receipt。
- 备份引用与 Bundle 只保存在本地，不推送到公开仓库；回滚以原始 `main` Commit 和 Bundle 为准。

## 风险与验证

- 历史重写会改变受影响 Commit SHA，并可能使既有 PR、CI 或外部链接指向旧历史；推送前输出旧、新 HEAD 和重写范围。
- 通过 Specflow Receipt 校验、Repository Check、Knowledge Check、完整 Git 敏感扫描和本地引用核对验证结果。
