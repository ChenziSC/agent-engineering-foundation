## 背景与目标

`project-context-bootstrap` 的正式 Replay 与真实样本对照已证明部分行为增益，但完整项目治理输入没有稳定降低上下文成本。普通有界任务没有触发 Bootstrap，仍出现显著输入增长，说明问题不能简单归因于单个 Skill。

本事项先把成本拆分为 Host 固有输入、项目规则、已安装 Skill、Context Resolver 计划、Active Spec/Knowledge 和任务代码取证，再用受控变体识别可重复的主要贡献。只有存在稳定增益和直接消费者时，才修改现有 Resolver 或采用内容；目标是在不损害治理行为的前提下减少普通任务的无关加载，而不是追求一次会话的最低 Token 数。

## 非目标

- 不建设通用 Skill 选择器、Capability Registry、Agent Runtime、Hook 或远端遥测；
- 不改变 Agent Host 的原生 Skill 发现、系统提示或计费方式；
- 不用删除安全规则、Evidence、不确定性或验证步骤换取表面 Token 下降；
- 不把规则就绪审计必须执行的全量 Skill 盘点优化成普通任务默认动作；
- 不在本事项内实现 Change Gate Git Provider；
- 不以单个真实项目证明长期、大型项目或其他 Host 已验证。

## 调用场景

1. Agent 在已接入治理骨架的项目中开始普通有界任务，只加载命中路径的规则、Active Spec、Knowledge 和代码入口，不枚举不适用 Skill。
2. 维护者明确发起项目规则或完整 Skill 就绪审计时，允许全量盘点，但输出需区分该专项成本与日常任务成本。
3. 维护者运行 `context resolve` 时，结果能够明确表达推荐加载集合和停止边界，避免把 `startPaths`、索引或未命中项误当成应全文加载内容。

## 输出与行为契约

- 先产出可复核的成本归因矩阵，区分事实、程序推导和 Agent 推断；
- 优化只进入既有 `context resolve`、Distribution/Bootstrap 采用内容或项目模板，不新增平行 Runtime；
- 普通任务不得因为安装了完整 Skill 集合而自动执行全量 readiness 审计；
- 成本结果只报告相同模型、提示、源码、沙箱和轮次下的方向性差异，同时保留工具结果体量与缓存造成的噪声边界；
- 未观察到稳定增益时停止实现，保留问题和实验结论，不创建空配置或抽象。
