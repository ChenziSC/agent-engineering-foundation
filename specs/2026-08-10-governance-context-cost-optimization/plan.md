# Plan：治理上下文成本归因与最小加载优化

## 对应 Spec

- 事项 ID：`2026-08-10-governance-context-cost-optimization`
- Spec：`./spec.md`

## 方案摘要

采用“静态盘点 → 单变量只读实验 → 决策门 → 最小实现 → 同条件回归”的路径。研究阶段不预设必须修改 Harness；如果主要成本来自完整 Skill 安装或采用内容，优先调整现有安装方式和触发/停止边界。如果 Resolver 的结构化输出确实诱发过度加载，再对现有契约做最小且向后兼容的增强。

## 实验变量

1. `current-full`：当前治理候选，保留完整项目 Skill 集合；
2. `selective-skills`：临时副本只保留当前任务直接相关的项目 Skill，不修改业务源码、规则、Knowledge；
3. `load-plan-stop`：在上一变体基础上明确只读取 Resolver `loadPlan` 和任务命中入口，除非 Evidence 要求不继续展开其他治理目录；
4. 若前三者不能解释回归，再评估根规则内容拆分；不提前删减规则。

每个变体使用同一普通有界任务、同一源码 revision、同一模型和只读沙箱，至少重复两轮。规则就绪审计只验证“显式专项仍能全量运行”，不以其绝对成本作为普通任务优化目标。

## 决策门结果

两轮实验未支持原先两个候选方向：

- `selective-skills` 平均输入约为 `795,286`，相对 `current-full` 的 `604,435` 高约 32%；命令轮次从平均 23 增至 53，说明减少已安装 Skill 不能约束 Agent 的后续取证路径；
- `load-plan-stop` 平均输入约为 `700,426`，高约 16%；命令输出体量虽平均下降，但模型轮次、代码与跨仓取证波动抵消了收益；
- 三组均出现临时副本缺少 Git 元数据或全局 Harness 命令的可恢复失败，计量只能用于否定“自然稳定降本”，不能形成精确性能阈值。

因此不修改 Distribution Manifest、不新增 Resolver 字段，也不把额外停止规则写入项目模板。进入实现的唯一窄改动是 **Specflow 主入口渐进披露**：普通规划任务每次都会读取 Specflow 主文件，而其中包含只在归档、关系事务和交付阶段需要、且已由 Reference 完整持有的细节。把这些重复细节从主文件缩减为按需路由，可以确定性降低每次 Specflow 触发的固定输入，不依赖 Agent 是否选择更多代码搜索。

## 数据流

```text
已归档成本回归
→ 静态输入盘点
→ 临时副本单变量只读会话
→ 行为质量 + 聚合成本归因
→ 决策门（无稳定收益则停止）
→ 最小实现
→ 相同任务回归 + 7 Case Replay + 仓库门禁
```

## 关键决策

| 决策 | 备选方案 | 选择理由 | 代价 |
| --- | --- | --- | --- |
| 先实验再改实现 | 直接压缩 AGENTS 或改 Resolver | 当前只有聚合 Token，无法可靠归因 | 增加数个只读会话成本 |
| 仅实施 Specflow 主入口渐进披露 | 选择性安装、Resolver 新字段或项目模板停止规则 | 前两者未显示稳定收益；主入口固定输入可确定性缩减且已有 Reference 承接细节 | 只改善固定治理输入，不保证端到端 Token 下降 |
| 保留规则审计专项全量能力 | 全面禁止枚举 Skill | 全量审计有明确消费者，只是不应默认发生 | 专项成本仍然较高 |

## Agent、程序与人工分工

- Agent：设计可比任务、判断行为质量、区分事实/推断、选择最小实现。
- 确定性程序：复制隔离样本、汇总事件计量、运行 Resolver/Replay/测试和门禁。
- 人工确认：归档、commit/push，以及成本与行为权衡是否接受。

## 兼容与迁移

- 向后兼容：现有完整安装继续可用，不自动删除采用方文件。
- 数据或配置迁移：默认不新增配置；若确需 Manifest 变化，先证明现有单 Skill 安装不足。
- 回退方式：内容变更可恢复为现有触发说明；程序变更保持旧字段语义并由测试覆盖。
