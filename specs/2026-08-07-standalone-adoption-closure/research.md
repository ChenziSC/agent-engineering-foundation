# Research：采用项目独立治理缺口基线

## 对应事项

- 事项 ID：`2026-08-07-standalone-adoption-closure`
- 对应 Plan 决策：把现有根包整理为可打包 CLI；路径优先的 Resolver；运行时 Skill 白名单。

## 问题与必要性

- 必须回答的问题：现有零依赖 Harness 能否以最小改造打包运行；哪些跨目录文件属于真实运行时；Resolver 如何在不引入自然语言模糊匹配的情况下保留路径路由；Distribution 如何安全清理旧受管非运行时文件。
- 为什么现有代码或文档证据不足：源码仓内执行会掩盖 Pack 缺文件；Doctor 通过不证明 Host PATH 或 CLI 包可用；完整复制 Skill 也无法证明资源最小；Resolver 正常 Case 没有覆盖未知任务类型加有效路径。
- 如果不回答，对方案有什么影响：采用项目仍依赖外部基础仓工作区；CI 无法固定执行入口；路由可能静默降级；Skill 更新持续制造非运行时噪声。

## 时间盒与判定标准

- 时间盒：T-01 至 T-03 的实现与定向测试阶段。
- 支持方案的证据：隔离 Pack 命令矩阵通过；运行时引用闭合；路径优先选择器 Case 通过；受管升级只清理已知旧文件。
- 否定方案的证据：必须复制全部仓库或引入运行时依赖才能执行；某个公开 Skill 的正常使用直接依赖 Eval/Test；路径优先无法避免不相关路由扩张。
- 到期仍不确定时的处理：保持事项 Active，缩减到已证明的 CLI 子集或保留完整 Skill 分发，不用文档声明替代实现证据。

## 当前结论

- 结果：`supported`
- 对 Plan 的影响：现有 Harness 已有清晰边界和零依赖实现，适合整理为 Pack，而不是重建 Runtime；Resolver 与 Distribution 缺口可以在现有数据模型上追加式修复。
