# Plan：成熟度投影一致性收敛

## 方案

1. 以正式 `skills/*/evals/replay.json`、确定性测试和真实 PR Evidence 为事实输入，区分行为成熟度、程序成熟度与采用范围。
2. 在 `docs/交付形态与成熟度.md` 校准成熟度，保留每项资产的证据与未覆盖边界。
3. 将能力地图和能力问题图谱中的“当前成熟度”改为“当前资产与证据/缺口”，删除重复标签和相对成熟度排名。
4. 同步长期 Knowledge 中 Bootstrap 的稳定结论，并用 Knowledge Projection 更新 Registry。
5. 将组件契约模板的自然语言标题改为中文，保留代码字段和通行技术术语。

## 关键决策

- `validated` 只表示需要语义判断的行为资产在声明范围内通过正式回放，不表示成本优化、真实长期采用或外部 Provider 已验证。
- `reference-implemented` 只描述有测试的确定性实现；同一能力可以由不同资产分别持有两种标记。
- 导航页可以陈述已有资产、测试、Replay 数量和下一缺口，但不再复制成熟度标签。
- 当前先通过内容所有权消除漂移，不为一次性文档一致性问题增加新的 Harness 抽象。

## 风险与回滚

- 风险：批量移除标签时丢失真实证据或缺口。控制：逐行保留资产事实，并对照唯一页面与 Replay 文件复查。
- 风险：把 Bootstrap 回放通过误写为上下文成本或大型项目验证。控制：将行为证据、成本观察和外推边界拆开。
- 回滚：本事项只修改自然语言与 Registry 摘要，可按文件恢复；不触及运行时契约。
