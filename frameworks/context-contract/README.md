# 契约化上下文框架

成熟度：`designed`

该框架解决“Agent 已经知道要加载哪些文件，但仍不知道哪些信息必须长期维护、哪些不能猜测、哪些应按任务实时推导”的问题。它不建设新的知识库，而是定义项目规则、稳定契约和动态切片之间的职责边界。

## 三层上下文

| 层级 | 典型内容 | 所有权与更新方式 | 不应包含 |
| --- | --- | --- | --- |
| 项目规则 | 仓库边界、目录职责、禁止事项、技术栈和入口路由 | 维护者拥有；Agent 可以提出有 Evidence 的修改候选 | 当前任务状态、长篇实现细节 |
| 稳定契约 | API/Schema、状态约束、不变量、兼容边界和关键流程 | Agent 可以从权威来源提取；维护者批准后由 Knowledge 管理 | 未确认推断、频繁变化的局部调用 |
| 动态切片 | 与当前任务相关的符号、数据元素、读写路径、异常分支和消费者 | Agent 针对候选版本实时生成；保存在当前 Spec 的 Plan、Research 或 Evidence 中 | 被当作长期事实静默复用 |

关键原则是：维护者对“Agent 不能猜测的内容”拥有最终批准权；Agent 负责从当前版本推导易变化的实现视图。人工所有权不表示必须手写全部契约，Agent 可以生成、刷新和解释候选。

## 与现有能力的边界

| 能力 | 拥有什么 | Context Contract 不做什么 |
| --- | --- | --- |
| Context Resolver | 决定本次任务加载哪些规则、Knowledge 和 Active Spec | 不判断契约内容是否正确 |
| Knowledge | 保存已批准的长期稳定事实、原因、契约和刷新条件 | 不保存动态切片和当前任务状态 |
| Specflow | 保存当前目标、方案、任务、验证和生命周期 | 不成为长期契约的第二正文源 |
| Evidence | 描述事实来源、适用范围、版本和 Claim 支持关系 | 不由 Contract 自行证明语义真实性 |
| Context Contract | 规定上下文形状、层级、所有权、来源和刷新边界 | 不复制上述状态，也不自动分析代码 |

## 最小采用流程

1. 从根规则、模块规则、代码入口、公开 Schema 和当前测试收集 Evidence。
2. 只把跨任务稳定且会影响正确性的内容写入 `project_rules` 或 `stable_contracts`。
3. 将缺少证据、存在冲突或需要维护者判断的内容写入 `unresolved`，不能补成确定事实。
4. 维护者批准稳定契约后，将其正文放入项目 Knowledge，并由 Registry 和 Code Entry Map 路由。
5. 每次任务根据入口、符号或数据元素生成 `dynamic_views`；动态产物进入当前 Spec，不直接写回长期 Knowledge。
6. 权威来源、入口或契约变化时，先标记 `review-required`，重新判断语义后再更新正文和摘要。

## 动态切片锚点

首版只定义通用锚点，不绑定编程语言或服务平台：

- `entrypoint`：路由、命令、事件、接口或用户场景入口；
- `symbol`：函数、组件、类型、配置项或其他可定位符号；
- `data_element`：请求字段、状态字段、Schema 属性或其他关键数据元素。

一个动态视图至少声明其中一个锚点。生成方式可以是人工阅读、Agent 检索、静态分析或采用方 Adapter；本框架不把任一方式伪装成已实现能力。

## 人工批准与 Evidence

- `draft` 表示候选尚不能作为不可猜测的稳定事实；
- `approved` 表示维护者已经批准当前版本和范围；
- `review-required` 表示来源、范围或契约发生变化，需要重新判断；
- Evidence 摘要只能证明来源版本一致，不能证明 Agent 对来源的解释正确；
- 同一设计生成的约束和检查清单不能独立证明该设计正确，仍需测试、运行观察、静态契约检查或人工 Review 等 Evidence 交叉验证。

## 公开与安全边界

- 模板和示例只使用合成项目、路径、接口与数据；
- 采用方的真实服务、拓扑、权限、配置和生产 Evidence 保留在采用方仓库；
- 公开仓只沉淀通用字段、流程、失败模式和验证边界；
- Context Contract 中的 `owner_role` 使用角色而非个人标识；
- 凭证、Prompt 原文、生产数据和个人信息不能进入 Contract。

从[合成模板](context-contract.template.json)开始采用，并用 [JSON Schema](context-contract.schema.json)检查基础结构。Schema 只能证明字段结构，不能证明来源存在、引用闭合、契约正确或 Evidence 独立。
