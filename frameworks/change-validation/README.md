# 增量覆盖与浏览器验证框架

成熟度：`reference-implemented`

该框架解决“只运行了一部分检查，却把整个变更当作已验证”的问题。它把变化路径、确定性检查、浏览器关键场景和人工门禁放入同一份显式矩阵，并由程序只判断结构覆盖和已记录结果。

## 核心原则

1. 每个变化路径必须至少命中一条覆盖规则；未映射路径不能静默通过。
2. 高风险规则可以同时要求自动检查、浏览器场景和人工门禁。
3. 浏览器验证必须记录页面、前置条件、动作、期望、版本和结果，不能只写“冒烟通过”。
4. `passed` 只表示声明的覆盖矩阵已经完成，不证明规则本身足以覆盖全部业务风险。
5. 采集器、测试框架和浏览器由采用方选择；核心不绑定供应商。
6. 设计说明和由其直接生成的检查清单只描述验证意图；只有在明确候选版本上执行得到的 Evidence 才能证明其覆盖范围内的行为，高风险契约还应说明是否需要不同消费者、机制、场景或独立 Review 交叉验证。

[Schema](change-validation.schema.json)、[模板](change-validation.template.json)和[参考实现](scripts/change-validation.mjs)可以直接复制到采用方项目。

参考实现只校验路径覆盖、结果状态和 Evidence 引用，不能从字符串或枚举判断 Evidence 是否真正独立。来源关系、共同盲区和规则是否充分由 Safe Change、Agent 或人工 Review 判断，不能为了自动化增加一个可随意填写的“独立”字段。
