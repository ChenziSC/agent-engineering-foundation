# 公开发布检查清单

本清单用于每个公开版本的最终候选快照，不替代法律意见、适用审批或代码托管平台的安全能力。上一版本通过不代表当前工作区自动通过。

## 一次性仓库设置

- [x] GitHub 仓库名称为 `agent-engineering-foundation`；
- [x] 本地目录和 README 使用相同名称；
- [x] `origin` 使用改名后的目标地址；
- [x] GitHub 仓库当前保持私有；改为公开必须作为独立发布动作重新授权；
- [x] Apache License 2.0 覆盖本仓 Agent 工程内容；
- [x] 发布前人工来源与权属复核已列为每个公开版本的必做项。

上述设置发生变化时必须重新检查，不能把勾选项当成永久事实。

## 当前版本权属与来源

- [ ] 本版本新增和修改内容已完成人工来源、公开处理等级、权属、脱敏结果和排除项复核；
- [ ] 公开内容不是受限正文、代码、Prompt、Schema、测试或目录结构的改名版本；
- [ ] 公开案例、URL、接口、版本和数据均为自行构造；
- [ ] 第三方代码、文档、图片和规范引用已记录来源、版本、许可和使用方式；
- [ ] 完成适用的权属、劳动合同、保密义务和内部审批复核；
- [ ] 二进制图片和其他文本扫描无法覆盖的资源已人工确认。

## 当前版本内容扫描

- [ ] 扫描最终工作区中的组织、平台、仓库、服务、员工和私有包名称；
- [ ] 扫描内部域名、接口、应用 ID、环境、Region、绝对路径和邮箱；
- [ ] 扫描 Token、Cookie、Header、密钥、证书和权限配置；
- [ ] 确认没有生产 Trace、HAR、截图、真实 URL、业务数据和内部故障码；
- [ ] 扫描 Git 历史、提交消息、已删除文件、Tag 和将要推送的对象；
- [ ] 对扫描命中项逐项人工复核，而不是只保留“扫描无结果”；
- [ ] 对最终暂存快照或准备推送的 Commit 再执行一次相同扫描。

启发式扫描未命中只能证明预设模式没有命中，不能代替权属和保密义务判断。

## 当前版本结构与质量

- [ ] 动态发现全部 Skill，并对每个目录执行结构校验，不使用手写固定数量；
- [ ] YAML、JSON、JSON Schema 和 Markdown 本地链接通过静态检查；
- [ ] `git diff --check` 通过；
- [ ] README、能力地图、目标结构和成熟度与实际目录一致；
- [ ] `validated` 行为资产存在正式行为回放证据，`reference-implemented` 资产存在与风险匹配的程序测试；
- [ ] `usable` 和 `designed` 资产没有被描述为已实现自动化；
- [ ] 新增或实质修改的 Skill 已增加或更新 Case 与 Rubric；
- [ ] Specflow、Knowledge、Starter 和 Harness 的状态与当前 Active Spec 一致；
- [ ] 所有未完成能力和发布 Blocker 在 Validation Report 中保持可见。

正式回放的 Skill 集合不在本清单中手写维护。发布候选应动态发现真实 Skill 目录，并按[交付形态与成熟度](交付形态与成熟度.md)逐项核对：标记为 `validated` 的 Skill 必须具有真实脱敏 Trace 和可重算 Replay 或等价正式回放。仍需人工复核 Trace 是否真实支持语义评分，程序通过不替代权属和保密判断。

### 自动化基线

`npm test` 验证最小 Harness 的写入与失败安全；`npm run check` 验证目录、JSON/JSON Schema、仓库采用的 YAML 子集、Markdown 本地链接、Skill/Eval 结构、无扩展名文本、敏感路径和高置信秘密格式。CI 示例位于 `.github/workflows/quality.yml`。

组织、平台、仓库、人员等专有词不能固化在公开仓中。维护者应把私有词表保存在仓库外，并通过 `repository check --deny-file <path>` 注入；报告只展示摘要。默认只扫描工作区，正式发布候选应执行 `repository check --deny-file <path> --git-scope all`，额外覆盖暂存区、分支与 Tag 可达历史、Reflog 和不可达对象。该自动化不检查二进制图片语义、远端平台中本地不存在的对象、权属或保密义务，相关清单项仍需人工完成。

## 当前版本 Git 与发布操作

- [ ] 审阅最终差异，确认没有夹带无关改动；
- [ ] Commit 作者和提交者使用预期的公开身份；
- [ ] Commit message 不包含内部工作项、平台、人员或业务信息；
- [ ] 提交已获得用户明确授权；
- [ ] 推送已获得用户明确授权；
- [ ] 推送后检查公开仓库默认分支、可见性、描述和文件内容；
- [ ] 如启用 Release、Pages、Package 或其他发布渠道，分别检查其制品和元数据。

仓库改名、归档、提交、推送、PR/MR 和发布是相互独立的动作，不能由其中一个推断其他动作已获授权。
