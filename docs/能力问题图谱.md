# 能力问题图谱

## 目的

本图谱回答“跨项目的 Agent 工程实际需要解决哪些问题”，而不是复刻任何来源仓库的文件结构。它由非公开覆盖台账投影而来，只保留通用问题、公开处理等级、当前资产和缺口，不包含来源路径、内部平台、真实案例或实现细节。

## 阅读方式

- 优先级表示对“任意项目快速接入 Agent 工程治理骨架”的价值，不表示必须同时编码；
- 公开等级表示允许沉淀的通用方案深度，不表示当前成熟度；具体表达与实现仍需权属复核；
- 成熟度沿用[交付形态与成熟度](交付形态与成熟度.md)；
- `idea` 也是有效盘点结论，但不能写成已经可用。

## 当前主要缺口

### P0：让治理骨架真正可接入

1. Specflow 的 Active 事项关系事务、三个及以上事项关系事务、跨仓库关系事务、其他版本控制 Provider，以及 Knowledge 正文与刷新触发的语义复核；
2. Change Gate 的受保护历史检查、外部交付平台证据和采用方策略扩展。

### P1：形成第二组可验证闭环

1. Knowledge Registry 与 Projection 已有参考实现，下一缺口是刷新触发的语义判断与更多代码入口分析；
2. 增量覆盖矩阵已实现，下一缺口是真实 Coverage 与 Browser Adapter；
3. 安全变更 Skill 已可用，下一缺口是与采用方提交/交付策略集成；
4. D2C 与埋点核心契约已实现，下一缺口是设计、浏览器、SDK 和数据平台 Adapter；
5. 差异感知质量门禁与 Repository Doctor 合并验证。

### P2：等待真实公开使用方

发布平台、需求系统、工作台账、领域查询和远端度量只有在出现真实采用方、直接消费者和相对宿主基线的增量证据后，才进入设计。没有这些证据时只保留问题条目，不提前创建完整工作流、状态机、Adapter 或 Registry。

## 依赖方向

```text
仓库上下文与 Knowledge
├── Context Resolver / Repository Audit
│   ├── 项目规则 / 稳定契约
│   └── 任务级 Evidence View
├── Semantic Slice Candidate
│   └── Language Adapter / Field Dataflow / Risk Rules
├── Specflow
│   ├── Archive / Lifecycle / Context
│   └── Change Gate / Knowledge Projection
├── Skill Source / Host-native Distribution
│   └── Skill Eval
├── Evidence
│   ├── 覆盖率与浏览器验证
│   ├── Web 性能与首屏预请求
│   └── D2C、埋点与安全变更
└── Harness / Doctor
    ├── 项目初始化与兼容发布检查
    └── 结构、引用、Schema 和发布门禁
```

后续新增能力时，必须先确认它解决的是新问题还是 Host 已有能力的具体场景，并记录宿主基线、增量缺口、直接消费者、验证与删除条件；无法回答时不创建资产。
