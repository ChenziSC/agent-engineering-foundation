# 脱敏与独立重写规范

## 核心原则

受限来源中的 Agent 能力全部进入非公开能力盘点；公开仓库再根据公开依据、权属和独立重建程度决定交付深度。能力来自受限来源不是排除理由，能力跨项目通用也不是当然公开的充分条件。

公开内容不能以内部材料为底稿逐句修改。正确方式是：

1. 在私有台账中记录要保留的能力点；
2. 关闭原始材料；
3. 从通用问题出发重新设计；
4. 使用新的命名、结构、接口和案例；
5. 用合成案例检查关键约束是否仍然存在；可使用 Skill 再补行为 Eval。

## 公开处理等级

| 等级 | 判断 | 处理方式 |
| --- | --- | --- |
| `full-rebuild` | 问题和方案均属通用工程实践，存在充分公开依据 | 独立编写完整设计、Skill、代码和合成测试 |
| `design-rebuild` | 通用方案可以公开，但原表达和实现不可复用 | 重新设计结构、接口、Schema、示例和实现 |
| `framework-only` | 具体组合或策略可能包含非公开独特信息 | 只公开问题、约束、原则、失败模式和扩展边界 |
| `exclude` | 公开依据不足、无法安全抽象或权属未确认 | 不进入公开 Git，只记录非公开处理结论 |

公开等级可以随公开依据、独立实现和权属复核结果调整，但不能通过简单改名从低等级升级为高等级。

## 可以保留的内容

- 通用问题类型；
- 抽象后的状态转换；
- 通用安全原则；
- 输入输出应该具备的字段类别；
- Agent 与程序的职责边界；
- 可公开验证的工程方法。

满足 `full-rebuild` 或 `design-rebuild` 条件时，不必把能力一律缩减为框架；可以保留完整状态机、决策规则、输入输出契约、Skill 工作流、验证方法和独立实现。

## 不进入公开仓库

- 公司、平台、仓库、服务和内部包名称；
- 内部域名、接口路径、应用 ID、Namespace、环境和 Region；
- 认证、Cookie、Token、Header 和权限申请方式；
- 员工姓名、邮箱、Owner、文档和工作项标识；
- 生产配置、Trace、HAR、截图、真实 URL 和业务数据；
- 内部故障码、真实发布限制和未公开平台行为；
- 从生产实践直接复制的精确阈值；
- 原仓库 Git 历史。

## 处理方式

| 原内容类型 | 公开版本处理 |
| --- | --- |
| 内部平台调用 | 定义通用 Provider 接口 |
| 真实生产案例 | 重新构造合成案例 |
| 业务 Schema | 重新设计最小通用 Schema |
| 固定阈值 | 改成可配置策略，并给出独立理由 |
| 平台特有失败 | 归纳成通用失败类别 |
| 内部操作手册 | 只保留安全状态机和人工门禁 |
| 内部测试 Fixture | 独立编写 Eval Case |

## 私有覆盖台账

私有台账只记录：

- 来源区域；
- 提取出的通用能力点；
- 目标模块；
- 公开处理等级；
- 通用价值判断；
- 公开依据与独立重建依据；
- 权属或保密状态；
- 排除项；
- 替代方式；
- 覆盖状态。

私有台账不得进入 Git。

## 公开依据检查

进入公开仓库前至少回答：

1. 这个问题是否在不同组织或个人项目中独立存在；
2. 解决方法是否有公开资料、公开规范或普遍工程实践支持；
3. 是否可以不依赖原表达、原代码、原 Schema、原 Prompt 和原案例完成设计；
4. 是否移除了内部平台、真实数据、特有阈值和可反推系统结构的信息；
5. 示例、测试和 Eval 是否全部为合成内容；
6. 是否仍存在合同、保密义务、职务成果或第三方许可方面的不确定性。

前五项通过不替代第六项的人工复核。扫描未命中也只能证明预设模式没有命中，不能单独证明内容可公开。

## 遥测与日志

- 默认关闭或只写本地；
- 不采集 Prompt；
- 不采集完整命令；
- 不采集工具输入输出；
- 不采集原始错误正文；
- 不采集邮箱和稳定个人标识；
- 远端上报必须显式开启，并提供字段清单、脱敏规则和保留周期。

## 发布前检查

1. 扫描工作区和 Git 历史；
2. 检查所有 Fixture 是否为合成数据；
3. 检查依赖和 API 是否公开；
4. 检查绝对路径、邮箱、内部域名和私有包名；
5. 检查遥测与日志；
6. 检查 License 和公开来源；
7. 完成需要的内部审批。
