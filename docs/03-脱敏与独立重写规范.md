# 脱敏与独立重写规范

## 核心原则

公开内容不能以内部材料为底稿逐句修改。正确方式是：

1. 在私有台账中记录要保留的能力点；
2. 关闭原始材料；
3. 从通用问题出发重新设计；
4. 使用新的命名、结构、接口和案例；
5. 用合成案例检查关键约束是否仍然存在；可使用 Skill 再补行为 Eval。

## 可以保留的内容

- 通用问题类型；
- 抽象后的状态转换；
- 通用安全原则；
- 输入输出应该具备的字段类别；
- Agent 与程序的职责边界；
- 可公开验证的工程方法。

## 不进入公开仓库

- 公司、平台、仓库、服务和内部包名称；
- 内部域名、接口路径、应用 ID、Namespace、环境和 Region；
- 认证、Cookie、Token、Header 和权限申请方式；
- 员工姓名、邮箱、Owner、文档和工作项标识；
- 生产配置、Trace、HAR、截图、真实 URL 和业务数据；
- 内部故障码、真实发布限制和未公开平台行为；
- 从生产实践直接复制的精确阈值；
- 原仓库 Git 历史。

## 处理方式

| 原内容类型 | 公开版本处理 |
| --- | --- |
| 内部平台调用 | 定义通用 Provider 接口 |
| 真实生产案例 | 重新构造合成案例 |
| 业务 Schema | 重新设计最小通用 Schema |
| 固定阈值 | 改成可配置策略，并给出独立理由 |
| 平台特有失败 | 归纳成通用失败类别 |
| 内部操作手册 | 只保留安全状态机和人工门禁 |
| 内部测试 Fixture | 独立编写 Eval Case |

## 私有覆盖台账

私有台账只记录：

- 来源区域；
- 提取出的通用能力点；
- 目标模块；
- 处理方式；
- 排除项；
- 替代方式；
- 覆盖状态。

私有台账不得进入 Git。

## 遥测与日志

- 默认关闭或只写本地；
- 不采集 Prompt；
- 不采集完整命令；
- 不采集工具输入输出；
- 不采集原始错误正文；
- 不采集邮箱和稳定个人标识；
- 远端上报必须显式开启，并提供字段清单、脱敏规则和保留周期。

## 发布前检查

1. 扫描工作区和 Git 历史；
2. 检查所有 Fixture 是否为合成数据；
3. 检查依赖和 API 是否公开；
4. 检查绝对路径、邮箱、内部域名和私有包名；
5. 检查遥测与日志；
6. 检查 License 和公开来源；
7. 完成需要的内部审批。
