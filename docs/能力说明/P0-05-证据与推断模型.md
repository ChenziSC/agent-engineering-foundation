# P0-05 证据与推断模型

## 定位

给定有明确来源和范围的观察材料，以及需要判断的主张，产出可引用、可验证、可失效的 Evidence 与 Claim 结构，防止 Agent 把推断描述成事实。

## 交付形态

- 当前：证据与推断设计框架 + v1 Schema + 零依赖封存/校验参考实现；
- 成熟度：`reference-implemented`；
- 当前边界：程序不判断 Evidence 来源真实性或 Claim 语义质量；
- 未来可选：更完整的确定性推导、ClaimStatus 规则引擎、Evidence 采集 Provider 和冲突检测。

当前产物：[Evidence 与 Claim 框架、v1 Schema 与参考实现](../../frameworks/evidence/README.md)。

## 调用与不调用条件

应该调用：

- Agent 需要依据工具、文件或人工确认得出结论；
- 结论只能在特定页面、版本、时间或场景下成立；
- 缺少部分证据但仍需要输出有限分析；
- 需要表达冲突、阻塞和验证动作。

不应调用：

- 只是持久化一次任务的执行阶段；
- 数据没有来源、范围或内容摘要；
- 调用方希望用置信度代替证据。

## 输入

必需输入：

- 原始观察或其安全引用；
- 来源类型、采集时间和适用范围；
- 内容摘要或完整性标识；
- 待验证的 Claim。

可选输入：

- 已有 Evidence 和 Claim；
- 确定性推导规则；
- 置信度；
- 反证和冲突证据；
- Verification 计划与结果。

## 输出契约

- `Evidence`：来源、范围、时间、内容摘要和有效状态；
- `Claim`：主张、类型、引用、置信度和当前状态；
- `Blocker`：缺失或无效证据阻断的具体 Claim；
- `Verification`：验证动作、预期观察和实际结果；
- `ValidationResult`：引用完整性、范围、冲突和失效检查；
- `ClaimStatus`：`supported`、`partial`、`blocked`、`refuted` 或 `stale`。

Claim 类型固定区分为观察事实、程序推导和 Agent 推断。

## 职责划分

Agent 负责：

- 提出 Claim；
- 解释 Evidence 与 Claim 的关系；
- 给出推断置信度及其理由；
- 设计需要人工判断的 Verification。

程序负责：

- 校验引用完整性和类型；
- 执行确定性推导；
- 检查 Evidence 范围、时间、摘要和冲突；
- 根据显式规则计算 ClaimStatus；
- 阻止没有 Evidence 引用的事实声明。

人工确认本身可成为一种 Evidence，但必须记录确认范围和时间，不能被解释为永久有效。

## 对象所有权与依赖方向

`evidence-core` 唯一定义：

- `Evidence`；
- `Claim`；
- `Blocker`；
- `Verification`；
- `ClaimStatus`；
- 证据引用和失效规则。

依赖规则：

- `evidence-core` 不依赖 `checkpoint-core`；
- Checkpoint 只能通过不透明 `ExternalRef` 引用 Evidence 或 Claim；
- Claim 过期、被反驳或被阻塞由 Evidence Core 判定；
- Checkpoint 可以记录相应运行事件，但不能复制或重新解释 Claim；
- 上层 Skill 或组合 Validator 负责把 ClaimStatus 转换成阶段退出门禁。

## 关键规则与安全边界

- 推断必须引用 Evidence；
- 部分 Evidence 可以继续分析，但必须标记范围；
- 一个 Blocker 只阻断它影响的 Claim；
- 共享模块 Evidence 不能自动变成某个页面事实；
- “报告不完整”和“报告没有价值”不是同一件事；
- 不允许用置信度掩盖没有证据；
- 不在 Evidence 中保存不必要的工具原始输入输出或敏感正文；
- 不负责持久化 Agent 执行生命周期。

## 合成应用案例

1. 合成 Trace 直接显示请求开始时间，Agent 应把时间标为观察事实。
2. 合成数据只覆盖共享模块，Agent 不得扩大为所有页面事实。
3. 两份合成 Evidence 对同一 Claim 相互冲突，应输出冲突和 Verification，而不是任选其一。
4. Evidence 内容摘要变化后，依赖 Claim 应变为 stale，并只阻断相关结论。

## 当前验收

- 提供对象定义、v1 JSON Schema、完整性封存和引用校验；
- 引用、范围、冲突和失效规则完整；
- Evidence Core 不依赖 Checkpoint；
- Checkpoint 集成只使用不透明引用；
- 四个合成案例可以按框架区分事实、推导和推断；
- 文档能够解释 partial、blocked、refuted 和 stale。
