# P0-09 契约化上下文与任务切片

## 定位

在 Agent 已经知道“应加载哪些文件”之后，进一步区分哪些信息必须长期维护、哪些不能猜测、哪些应针对当前 revision 实时推导，并用有限上下文支持当前任务。

## 当前交付形态

- [Context Contract Framework](../../frameworks/context-contract/README.md)：`designed`，定义项目规则、稳定契约和动态切片三层模型；
- [`project-context-bootstrap` Skill](../../skills/project-context-bootstrap/SKILL.md)：`validated`，提供最小 Bootstrap 与任务 Slice；
- Context Resolver / Section Index：`reference-implemented`，负责确定性路由、预算和大型 Markdown 导航。

三者互补：Resolver 决定加载候选，Section Index 降低大型 Spec 的读取成本，Skill 读取相关原文并生成任务语义关系。Skill 不替代前两者。

## 调用条件

应该调用：

- 存量项目首次接入 Agent，需要建立最小项目上下文；
- Agent 缺少可靠的仓库边界、稳定不变量或代码入口；
- 当前任务需要定位入口、符号、数据字段、直接消费者、异常和测试；
- Active Spec 超预算，只能先通过 Section Index 选择章节。

不应调用：

- 只需要查看一个明确文件或修改孤立文本；
- 试图替代 Codex、Claude Code 等宿主的上下文窗口或压缩；
- 需要完整 AST、调用图、运行态拓扑或外部消费者证明；
- 希望无证据自动生成长期 Knowledge。

## 数据流

```text
任务目标与目标路径
→ Context Resolver 选择规则、Knowledge 和 Active Spec
→ 超预算 Spec 返回 Section Index
→ Agent 读取相关章节原文
→ project-context-bootstrap 选择 bootstrap 或 slice
→ 以 entrypoint / symbol / data_element 为锚点收集仓库证据
→ 输出 observed / inferred / unresolved 与停止边界
→ 稳定候选等待批准；动态切片进入当前 Spec
```

## 切片边界

首版默认只扩展直接关系，并选择一条影响当前判断的关键数据链。只有转发层、深层转换、异常/权限/缓存/兼容行为或测试边界要求时才继续深入。到达公开契约、已有稳定 Knowledge、第三方边界或无关模块时停止。

静态搜索不能证明动态注册、反射、运行时注入和外部消费者的全集；缺少相应 Evidence 时输出 `partial` 或 `unresolved`。

## 状态所有权

| 内容 | 所有者 |
| --- | --- |
| 仓库和模块必须遵守的规则 | 根级/模块级 Agent 规则 |
| 经批准的稳定契约与刷新条件 | Knowledge |
| 当前需求、方案、任务和生命周期 | Specflow |
| 当前 revision 的调用链、数据链和消费者 | Spec Research / Evidence |
| 全文预算和 Markdown 章节导航 | Context Resolver / Section Index |

## 当前验证

- Skill Creator 标准目录与 UI 元数据；
- 中文 Skill、两份输出模板、详细边界与失败模式；
- 4 个合成行为案例覆盖存量 Bootstrap、Section Index 消费、有界任务切片和动态消费者盲区；
- 本仓 Skill Check、Distribution 与 Repository Check 提供结构验证。

- 独立正式 Eval Replay 在合成项目和本仓回放 4/4 Case，平均分 100，无阻塞项；Distribution Plan/Apply/Verify、Repository Check 和整仓测试通过。

正式脱敏 Trace 和可重算 Replay 已补齐，当前 Skill 标记为 `validated`；这不等同于真实采用方长期复核，也不覆盖语言级或运行态消费者分析。

## 后续工程化

- 在真实存量项目执行最小 Bootstrap 并保存脱敏行为 Evidence；
- 按采用方需要增加语言级符号、调用关系或运行态消费者 Adapter；
- 用真实 Eval 数据调整扫描深度，不先建设完整分析平台。
