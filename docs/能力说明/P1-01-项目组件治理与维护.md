# P1-01 项目组件治理与维护

## 定位

给定可访问的项目仓库和组件需求，基于源码、契约、索引、示例和调用方证据，产出组件复用、薄封装、扩展、新建、分层准入、迁移或废弃决策，并明确验证与人工确认边界。

这项能力管理项目中的全部组件来源，不等同于共享组件库维护。

## 交付形态

首期交付：

- [设计框架](../../frameworks/project-component-governance/README.md)；
- [可使用 Skill](../../skills/project-component-governance/SKILL.md)；
- [组件治理模板](../../templates/project-component-governance/README.md)；
- [仓库接入 Blueprint](../../blueprints/project-component-governance/README.md)；
- 七个完全合成的行为 Eval Case、Rubric、脱敏 Trace 和可重算 Replay；
- Registry Validator、Schema 和合成程序测试。

首期成熟度：

- Framework：`designed`；
- Skill：`validated`；
- Template：`usable`；
- Blueprint：`designed`；
- Registry Validator 子集：`reference-implemented`。

正式回放覆盖七个 Case；Runner 可重算 Trace 摘要、Case 全量覆盖和阻塞优先评分。该结论不把程序结构检查解释为组件抽象价值证明。

## 触发条件

适合：

- 新增或重写组件前判断是否已有可复用能力；
- 判断组件应留在页面、应用还是项目共享层；
- 评审标准组件准入；
- 修改或迁移历史组件；
- 扩展公开组件 API；
- 废弃、替换或合并组件；
- 检查组件索引、契约和维护边界。

不适合：

- 只有截图且无法访问任何仓库或组件文档；
- 仅要求从设计稿生成视觉代码；
- 只运行已经明确的测试命令；
- 只执行 Package 发布；
- 把所有组件无差别迁入共享包。

## 输入

必需输入：

- 待实现、待修改或待评审的组件需求；
- 可访问的组件源码、Contract、Registry 或正式组件文档中的至少一种。

可选输入：

- 设计稿、截图或交互说明；
- 目标页面、运行端和框架；
- 已知候选组件；
- 调用方与版本范围；
- 历史迁移、故障或重复建设记录。

允许的假设必须显式标记。缺少仓库和组件文档时停止，不根据常见目录或组件名编造项目事实。

## 输出契约

输出包含：

- `complete | partial | blocked` 状态；
- 仓库、版本、目标模块和证据范围；
- 候选组件及证据；
- `reuse | wrap | extend | new-local | promote` 决策；
- 被排除方案及理由；
- 放置层级与准入检查；
- 兼容、迁移或废弃风险；
- 风险匹配的验证计划；
- 人工确认项。

`complete` 表示当前治理决策有足够证据，不表示组件已经实现、迁移或发布。

## 核心模型

放置层级：

```text
页面本地 → 应用共享 → 项目共享 → 项目标准
```

生命周期：

```text
candidate → active → deprecated → retired
                ↘ migrating ↗
```

两个维度相互独立。放置层级描述复用范围和治理承诺，生命周期描述当前维护状态。

## 职责划分

### Agent

- 理解组件语义、状态和交互；
- 发现并比较候选；
- 判断复用价值、放置层级和抽象边界；
- 设计迁移、废弃和验证方案；
- 区分事实、程序检查和 Agent 判断。

### 程序

- 解析目录、Registry、Contract 和导出；
- 检查命名、路径、链接和深路径引用；
- 运行构建、类型检查和测试；
- 在 Git Hook 或 CI 中执行结构门禁。

### 人工

- 确认争议性抽象边界和维护责任；
- 批准破坏性 API 变化；
- 批准批量迁移、删除公开入口和发布。

程序门禁不能证明组件具有跨场景价值，Agent 建议也不能代替发布授权。

## 依赖与状态所有权

- 复用 [Skill 行为评估](../../frameworks/skill-eval/README.md)的方法与模板；
- 可以复用 [Evidence 框架](../../frameworks/evidence/README.md)表达事实、推导、推断和阻塞项；
- 可以作为 [AI 友好仓库模板](../../templates/ai-friendly-repository/README.md)的可选增强；
- 组件 Registry 是层级、状态、位置和 Contract 入口的唯一事实来源；
- Component Contract 是公开 API 与使用边界的唯一说明；
- 源码和可重复验证是当前运行行为的事实来源；
- 单次 Decision Report 不回写成永久组件事实。

不复制 Evidence、Eval 或仓库指令中的通用概念，只引用现有能力。

## 非目标与安全边界

- 不复制任何真实项目组件源码、组件列表或业务契约；
- 不要求固定前端框架、目录或设计系统；
- 不自动迁移、删除或发布组件；
- 不把视觉相似当作 API 兼容证据；
- 不记录真实生产数据、内部账号或稳定个人标识；
- 不以“以后可能复用”为标准准入依据；
- 不用目录门禁替代语义准入评审。

## 合成应用案例

### 案例一：直接复用

已有异步数据表格覆盖加载、空态、错误和重试，新页面只改变列和文案。Skill 必须选择 `reuse`。

### 案例二：薄封装

现有选择器满足交互，新接口字段结构不同。Skill 必须选择 `wrap`，并将数据转换留在业务侧。

### 案例三：保留本地

页面侧栏依赖路由、权限和多个业务请求，且只有一个调用方。Skill 必须选择 `new-local`。

### 案例四：提升标准层

两个独立应用需要相同的文件预览卡片。Skill 可以选择 `promote`，但必须要求稳定 API、依赖、Contract、Registry、导出和验证。

### 案例五：历史迁移

旧组件存在深路径调用，目标实现改变默认行为。Skill 必须输出兼容迁移和回滚计划，不得只建议移动目录。

### 案例六：证据不足

只有截图且没有仓库。Skill 必须返回 `blocked`，不能给出具体组件或路径。

## 文档首版验收

- Skill 通过结构校验；
- Framework、Skill、Template 和 Blueprint 职责不重复；
- 至少覆盖发现、准入、迁移、废弃和阻塞案例；
- Skill 具有行为 Eval Rubric 和合成 Cases；
- YAML 示例可解析；
- 所有相对链接有效；
- 不含真实公司、项目、包、组件、人员或平台标识；
- 正式回放与程序测试可重算，且验证边界保持可见。

## 未来可选工程化

满足真实复用条件后，可以增加：

- 其他语言的公开导出与 Contract 正文解析器；
- 基于编译器或构建图的完整调用方与类型兼容差异扫描器；
- 迁移前后公开结构比较器；
- Registry 生成器；
- 本地优先、隐私受控的治理指标。

不默认建设组件生成器、设计稿转码、Package 发布器或统一文档站。
