# P0-07 AI 友好仓库

## 定位

给定一个代码仓库、权威规则和长期知识，产出分层的 Agent 上下文入口、知识注册表和健康检查报告，使 Agent 能用最小上下文找到当前任务所需信息。

## 交付形态

- 首期：可复制的仓库模板 + 人工检查清单；
- 成熟度目标：`usable`；
- 首期不要求：Health Check 脚本、自动路由或程序测试；
- 未来可选：确定性的仓库上下文检查工具。

当前产物：[AI 友好仓库模板](../../templates/ai-friendly-repository/README.md)。

## 调用与不调用条件

应该调用：

- 仓库准备接入编码 Agent；
- 全仓规则、模块规则和长期知识混杂；
- Agent 经常加载过多上下文或遗漏权威规则；
- 需要检查知识过期、冲突和路由错误。

不应调用：

- 只想为单次任务保存进度；
- 仓库没有稳定规则或长期知识；
- 用户希望把全部文档无差别注入上下文。

## 输入

必需输入：

- 仓库结构；
- 全仓必须遵守的规则；
- 主要代码入口和模块边界。

可选输入：

- 模块级规则；
- 长期架构知识；
- 当前 Specflow 产物；
- 已有 Agent 指令文件；
- 文件更新时间和责任范围。

## 输出契约

- `root-instructions`：全仓不变量、模块地图和工作流；
- `module-instructions`：规则密集模块的局部约束；
- `knowledge-registry`：长期知识的范围、入口和新鲜度；
- `code-entry-map`：任务类型到代码入口的映射；
- `context-routing-report`：给定任务应加载哪些上下文；
- `health-report`：冲突、过期、重复和体量问题。

当前任务状态只通过 Specflow 等交付产物引用，不复制进长期知识。

## 职责划分

Agent 负责：

- 判断规则和知识属于哪一层；
- 识别稳定知识与一次性进度；
- 总结模块边界和历史原因；
- 解释冲突及修复建议。

程序负责：

- 校验 Registry Schema；
- 检查路径、引用、体量和更新时间；
- 发现重复规则和明显冲突；
- 根据显式映射生成上下文路由；
- 输出确定性的健康报告。

删除、覆盖已有规则或改变权威来源时需要用户确认。

## 信息分层与状态所有权

### 根规则

只保留全仓不变量、模块地图和必须遵守的工作流。

### 模块规则

只在规则密集、模式稳定的目录增加，避免每个目录都放一份说明。

### 长期知识

记录稳定的架构、契约、历史原因和常见失败，不记录一次性进度。

### 当前交付产物

记录本次需求的范围、方案和任务，是当前状态的唯一事实来源；知识层只保存引用。

首期目标落点为：

```text
templates/ai-friendly-repository/
├── root-instructions/
├── module-instructions/
├── knowledge-entry/
├── knowledge-registry/
└── review-checklist/
```

## 非目标与安全边界

- 不把所有文档自动加入上下文；
- 不把聊天摘要当作长期知识；
- 不为每个目录生成重复规则；
- 不自动删除被判断为过期的知识；
- 不在公开模板中包含真实仓库路径、人员或内部平台信息；
- 不代替 Specflow 管理当前交付状态。

## 首期资源

- 指南：分层原则、准入规则、冲突与过期模式；
- 模板：根规则、模块规则、知识条目、Registry 和检查清单；
- 合成案例：重复规则、错误路由、知识过期和状态混层；
- `scripts/`、`evals/` 和 `tests/`：首期不需要。

## 合成应用案例

1. 合成单体仓库包含重复全局规则，应合并权威来源而不是复制到每个模块。
2. 合成模块规则只适用于前端目录，路由时不得注入后端任务。
3. 合成长期知识引用的代码入口已经删除，应报告过期但不自动删除知识。
4. 合成任务进度被错误写入长期知识，应建议迁移到当前交付产物。

## 模板首版验收

- 提供可复用的 AI 友好仓库模板目录；
- 根规则、模块规则、知识条目、Registry 和检查清单完整；
- 人工检查清单覆盖路由、冲突、过期和体量；
- 当前交付状态与长期知识保持单一事实来源；
- 四个合成案例可以用模板和检查清单走查。
