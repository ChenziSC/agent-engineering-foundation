# 能力说明模板

所有 P0 能力使用同一组问题描述边界。Skill 使用“触发条件”，框架、Package、Adapter 和检查器使用“调用条件”。

## 定位

用一句话说明：给定哪些输入，产出什么，并满足哪些关键约束。

## 问题与公开边界

- 解决的真实工程问题；
- 为什么该问题跨项目成立；
- 可以支持解决思路的公开规范、公开资料或普遍工程实践；
- 公开处理等级：`complete-solution`、`adapter-backed`、`problem-pattern` 或 `exclude`；
- 已移除的内部依赖和不能公开的部分；
- 通用设计及其组合来自何种工程问题，哪些内容被直接保留；公开表达、案例和实现是自行编写还是具有明确授权；
- 尚待人工确认的权属、保密义务或第三方许可问题。

公开仓库不记录受限来源路径和映射；这些信息只存在于非公开覆盖台账。

## 交付形态

- 首期属于设计框架、Blueprint、模板、可使用 Skill 还是参考实现；
- 首期必须交付什么；
- 哪些 Package、Adapter、脚本或测试只是未来可选工程化内容。

## 触发或调用条件

- 什么时候应该触发或调用；
- 什么时候不应该触发或调用；
- 缺少哪些信息时必须补问、降级或停止。

## 输入

- 必需输入；
- 可选输入；
- 输入来源；
- 允许显式作出的假设。

## 输出契约

- 结构化输出；
- 输出状态；
- 最低质量标准；
- 部分成功或阻塞时如何表达。

## 职责划分

分别说明：

- Agent 负责的理解、判断和权衡；
- 程序负责的解析、校验、比较、持久化和门禁；
- 必须由人工确认的动作。

纯设计框架或 Package 可以把 Agent 职责写为“由调用方负责”，但不能省略边界。

## 依赖与状态所有权

- 依赖哪些 Package、Adapter 或外部输入；
- 被哪些能力复用；
- 哪个模块是每类状态的唯一事实来源；
- 明确禁止的反向依赖和数据复制。

## 非目标与安全边界

- 首版不解决什么；
- 哪些情况只能输出有限结论；
- 哪些外部写操作必须显式授权；
- 哪些数据不得进入日志、遥测和示例。

## 资源计划

- `references/`：稳定知识、规范和失败模式；
- `assets/`：模板、Schema 示例和输出骨架；
- `scripts/`：只有已经决定实现的确定性重复动作；
- `evals/`：可使用 Skill 的行为案例和评分标准；
- `tests/`：只覆盖实际存在的确定性程序。

纯框架和 Blueprint 可以只使用 Markdown、图示、模板和合成案例。没有对应资源时写明“不需要”及原因，不创建空目录。

## 合成应用案例

首版至少定义三个完全合成的案例。纯框架用于人工走查，可使用 Skill 才需要转成正式 Eval Case。每个案例至少包含：

- 用户请求或调用场景；
- 输入材料；
- 必须执行的动作；
- 禁止执行的动作；
- 必须产出的内容；
- 阻塞条件；
- 评分规则。

## 文档首版验收

列出与当前交付形态相匹配、可以客观检查的条件。不能把未来可选参考实现写成当前阻塞条件。

## 未来可选工程化

只有确实计划实现时，才列出：

- Package、CLI、Adapter 或脚本；
- Schema 和公开接口；
- 测试；
- 自动化 Eval；
- 版本和兼容要求。
