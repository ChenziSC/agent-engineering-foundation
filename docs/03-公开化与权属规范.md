# 公开化与权属规范

## 核心原则

受限来源中的 Agent 能力全部进入非公开能力盘点；公开仓库根据内容是否通用、是否已移除具体内部信息，以及表达与实现的权属决定公开深度。能力来自受限来源不是排除理由；多个通用细节形成的状态机、流程、职责或模块排布也不因其组合方式自动成为敏感信息。公开等级与交付成熟度是两个维度：前者回答“可以保留多少通用方案”，后者回答“当前实现和验证到了哪里”。

公开内容不能只替换内部名称后照搬仍受限制的文字、代码、Schema、测试或数据。通用解决方案可以作为设计输入并保留其必要组合。处理方式是：

1. 在私有台账中记录要保留的能力点；
2. 区分通用问题/解决思路与具体内部事实/专有实现表达；
3. 保留跨项目成立的状态机、步骤顺序、职责划分、接口类别和多细节组合，不为制造差异而重排；
4. 移除内部标识、真实拓扑、平台行为、配置、数据和权限信息；公开文字、代码、Schema 与案例自行编写，除非已有明确复用权；
5. 用合成案例检查关键约束是否仍然存在；可使用 Skill 再补行为 Eval。

## 公开处理等级

| 等级 | 判断 | 处理方式 |
| --- | --- | --- |
| `complete-solution` | 问题、通用流程、状态机、职责、契约和验证方法可以完整公开 | 完整保留通用方案；具体表达、Skill、代码、Schema 和合成测试自行编写或基于明确许可 |
| `adapter-backed` | 通用方案可以完整公开，但执行依赖采用方自己的平台、环境或领域映射 | 保留完整工作流与核心契约；把平台调用、真实拓扑、字段和认证隔离到 Adapter |
| `problem-pattern` | 通用问题成立，但尚无稳定的跨项目完整方案 | 公开问题、约束、失败模式、决策因素和形成完整方案所需的验证条件 |
| `exclude` | 内容本身仍含无法去除的内部事实，或具体表达/实现无法合法公开且无法自行编写 | 不进入公开 Git，只记录非公开处理结论 |

公开等级可以随通用性证据、内部信息移除情况和权属复核结果调整，但不能通过简单改名升级。`adapter-backed` 不是低成熟度或残缺方案：它应保留端到端通用流程，只把采用方专有实现留在仓外。

## 可以保留的内容

- 通用问题类型；
- 抽象后的状态转换；
- 通用安全原则；
- 输入输出应该具备的字段类别；
- Agent 与程序的职责边界；
- 可公开验证的工程方法。
- 多个通用细节组成的完整流程、状态机、模块排布和解决策略。

满足 `complete-solution` 或 `adapter-backed` 条件时，不必把能力缩减为框架；可以保留完整状态机、决策规则、输入输出契约、Skill 工作流、验证方法和独立实现。

## 不进入公开仓库

- 公司、平台、仓库、服务和内部包名称；
- 内部域名、接口路径、应用 ID、Namespace、环境和 Region；
- 认证、Cookie、Token、Header 和权限申请方式；
- 员工姓名、邮箱、Owner、文档和工作项标识；
- 生产配置、Trace、HAR、截图、真实 URL 和业务数据；
- 内部故障码、真实发布限制和未公开平台行为；
- 真实内部系统拓扑、服务关系、权限边界和环境映射；
- 从生产实践直接复制的精确阈值；
- 原仓库 Git 历史。

## 处理方式

| 原内容类型 | 公开版本处理 |
| --- | --- |
| 内部平台调用 | 定义通用 Provider 接口 |
| 真实生产案例 | 重新构造合成案例 |
| 业务 Schema | 重新设计最小通用 Schema |
| 固定阈值 | 改成可配置策略，并给出独立理由 |
| 平台特有失败 | 归纳成通用失败类别 |
| 内部操作手册 | 只保留安全状态机和人工门禁 |
| 内部测试 Fixture | 独立编写 Eval Case |

## 私有覆盖台账

私有台账只记录：

- 来源区域；
- 提取出的通用能力点；
- 目标模块；
- 公开处理等级；
- 通用价值判断；
- 通用性、内部信息移除情况，以及具体表达和实现的自行编写或复用权依据；
- 权属或保密状态；
- 排除项；
- 替代方式；
- 覆盖状态。

私有台账不得进入 Git。

## 公开边界检查

进入公开仓库前至少回答：

1. 这个问题是否在不同组织或个人项目中独立存在；
2. 解决方法是否有公开资料、公开规范或普遍工程实践支持；
3. 公开文字、代码、Schema、Prompt 和案例是否为自行编写或具有明确复用权；
4. 是否移除了内部平台标识、真实数据、真实拓扑、私有平台行为、特有阈值和权限信息；通用细节的组合本身不作为否决项；
5. 示例、测试和 Eval 是否全部为合成内容；
6. 是否仍存在合同、保密义务、职务成果或第三方许可方面的不确定性。

前五项通过不替代第六项的人工复核。扫描未命中也只能证明预设模式没有命中，不能单独证明内容可公开。

## 遥测与日志

- 默认关闭或只写本地；
- 不采集 Prompt；
- 不采集完整命令；
- 不采集工具输入输出；
- 不采集原始错误正文；
- 不采集邮箱和稳定个人标识；
- 远端上报必须显式开启，并提供字段清单、脱敏规则和保留周期。

## 发布前检查

1. 扫描工作区和 Git 历史；
2. 检查所有 Fixture 是否为合成数据；
3. 检查依赖和 API 是否公开；
4. 检查绝对路径、邮箱、内部域名和私有包名；
5. 检查遥测与日志；
6. 检查 License 和公开来源；
7. 完成需要的内部审批。
