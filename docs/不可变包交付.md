# Foundation 不可变包交付

Foundation 的正式采用版本必须同时绑定 SemVer、不可变 Source Commit 和可校验制品摘要。`npm pack` 成功只证明包可生成，不等于已经获准公开发布。

## 制品契约

在干净、已提交且已完成回归的候选上运行：

```bash
npm run release:pack -- --target . --output /absolute/release-output
```

输出包含一个 npm tarball 和 `release-manifest.json`。清单记录包名、SemVer、文件名、字节数、SHA-256、npm integrity、npm shasum 与 40 位 Source Revision。命令发现未提交或未跟踪内容、既有 Release Manifest、无效包版本或无法解析的 Git Commit 时失败关闭，不覆盖已有制品证据。

## npm 公共发布

公开包固定发布到 `https://registry.npmjs.org/`。维护者先独立授权并创建 `v<package-version>` Tag，再手动触发 `publish-npm` Workflow。Workflow 复核 Tag 与公共包元数据，运行全量与规模回归，验证本仓 Doctor/Distribution，生成唯一 tarball 与清单，然后把该 tarball 发布到 npmjs.org 并回读 Registry integrity。

Workflow 使用公开 GitHub 仓库的 Actions 环境生成 npm Provenance，但不创建 GitHub Release。首发通过仓库 Secret `NPM_TOKEN` 使用最小权限 npm Granular Token；Secret 值不得进入源码、日志、Spec 或聊天。包创建后优先迁移 npm Trusted Publishing，并撤销首发 Token。

Workflow 文件、Tag 或 Run 存在不代表 npm 发布成功。重试时先读取 `name@version` 的 Registry integrity：不存在才允许发布；已存在且与本次 Manifest 相同则跳过重复上传；不一致时失败关闭。npm 版本一旦公开，不覆盖或重用版本号，修复使用新的 SemVer。

发布完成后分别复核：

```bash
npm view agent-engineering-foundation@<version> dist.integrity --registry=https://registry.npmjs.org/
npm exec --yes --package=agent-engineering-foundation@<version> -- agent-foundation --version
```

Registry integrity、Provenance、Git Tag 和 Source Revision 是不同证据，不能互相替代；它们也不证明采用项目的 Host、配置或外部 Adapter 已经就绪。
