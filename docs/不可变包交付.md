# Foundation 不可变包交付

Foundation 的正式采用版本必须同时绑定 SemVer、不可变 Source Commit 和可校验制品摘要。`npm pack` 成功只证明包可生成，不等于已经获准公开发布。

## 制品契约

在干净、已提交且已完成回归的候选上运行：

```bash
npm run release:pack -- --target . --output /absolute/release-output
```

输出包含一个 npm tarball 和 `release-manifest.json`。清单记录包名、SemVer、文件名、字节数、SHA-256、npm integrity、npm shasum 与 40 位 Source Revision。命令发现未提交或未跟踪内容、既有 Release Manifest、无效包版本或无法解析的 Git Commit 时失败关闭，不覆盖已有制品证据。

## GitHub 当前 Provider

本仓当前真实远端是 GitHub，因此提供手动 `release` Workflow：维护者先独立授权并创建 `v<package-version>` Tag，再手动触发 Workflow。Workflow 复核 Tag、运行全量与规模回归、验证本仓 Doctor/Distribution，生成制品与清单，最后创建 GitHub Release。

Workflow 文件存在不代表 Tag、Release 或公开发布已经获准或执行。GitHub Release Asset 可被具有权限的维护者替换，因此采用方还必须保存并复核 `release-manifest.json` 中的 SHA-256；只固定可变 URL 不构成不可变版本。

其他 Git Provider 出现真实发布消费者后，再提供对应薄 Workflow；核心包格式与清单不包含平台分支。
