# 公开内容来源说明

## 适用范围

本说明适用于仓库中的 Agent 工程框架、Skill、Blueprint、模板、Schema 示例和合成案例。

`pets/` 中的名称、说明和图片资源已经由仓库维护者确认可以随仓库公开分发。

## 编写方式

Agent 工程内容按照以下方式形成：

1. 从跨项目可复用的工程问题出发重新定义能力边界；
2. 将受限来源中的 Agent 能力全部纳入非公开盘点，再按通用性、内部信息移除情况和具体表达/实现的复用权选择完整重建、设计重建、仅保留框架或排除；
3. 保留跨项目成立的问题、状态机、步骤顺序、职责划分、模块排布和通用细节组合；
4. 不仅替换内部名称后复制受限文字、代码、Schema、测试或数据；公开表达和实现自行编写或基于明确授权；
5. 使用自行构造的 URL、数据、场景和失败条件；
6. 将外部平台能力隔离为 Provider 或 Adapter 边界；
7. 通过私有覆盖台账记录来源区域、公开目标、处理等级、排除项和替代方式，但不公开原始来源信息。

通用能力不会仅因来自受限来源或由多个细节组合而被排除。组合后的通用流程和解决策略可以完整沉淀；只有其中实际存在的内部标识、真实拓扑、私有平台行为、配置、数据、权限和专有实现表达需要过滤。具体文字和代码能否直接复用仍取决于权属、许可和必要的人工复核。

内容编写使用了生成式 AI 辅助，最终结构、边界和公开内容由仓库维护者负责复核。

项目组件治理与维护能力只保留跨项目成立的问题模型、决策类型、生命周期、职责边界和合成案例。公开内容没有纳入任何真实项目的组件源码、组件清单、内部包名、设计系统名称、业务契约、人员信息或平台链接。

## 公开规范

Schema 示例采用 JSON Schema Draft 2020-12 的公开方言标识：

- [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12)

引用公开规范只表示遵循其数据格式，不表示复制规范正文。

## 第三方内容

当前 Agent 工程内容没有直接纳入第三方代码、文档正文、测试数据或图片。若后续增加第三方内容，应在合入前记录：

- 来源链接；
- 作者或维护组织；
- 许可证及版本；
- 使用或改编方式；
- 需要保留的声明。
