# 项目组件治理约束

## 发现优先

- 新增或重写组件前，先检索 `<组件 Registry 或文档入口>`。
- 按页面本地、应用共享、项目共享、已安装基础组件的顺序查找候选。
- 命中候选后读取组件 Contract、公开导出、Story/Demo 和相关调用方。
- 没有证据时不得仅根据名称或视觉相似声称可以复用。

## 决策

- 核心能力一致时优先 `reuse`。
- 只有数据转换、默认值或上下文差异时使用业务侧 `wrap`。
- 新能力可复用且能保持兼容时评估 `extend`。
- 单页面、强业务依赖或复用未被证明时使用 `new-local`。
- 只有多个独立场景、稳定 API、可共同消费的依赖和完整治理资产都成立时，才允许 `promote`。

## 标准组件

- 标准组件目录：`<项目配置的标准目录>`。
- Registry：`<Registry 路径>`。
- Contract 命名：`<组件名>.md`。
- 稳定导出入口：`<包或模块入口>`。
- 禁止深路径导入：`<项目定义的禁止模式>`。

## 维护

- 修改历史或公开组件前先扫描调用方。
- 破坏性变化必须提供兼容策略、迁移窗口和回滚方式。
- 废弃组件必须声明替代项；删除公开入口需要明确授权。
- Agent 负责语义和边界判断，程序负责结构、导出、链接、构建和测试门禁。
