# Knowledge：通用能力的公开与脱敏复用

## 注册信息

- ID：`public-generalization-policy`
- 状态、适用范围、复核时间、权威来源和刷新条件以 [Knowledge Registry](registry.yaml) 中的同 ID 条目为准。

## 摘要

受限来源中的 Agent 能力可以用于识别真实问题和工程价值。公开仓库不按来源或通用细节的组合方式过滤，而是根据内容是否通用、是否已移除具体内部信息，以及表达与实现的权属状态决定交付深度；维护者在每次公开发布前完成人工来源与权属复核。

## 稳定事实

- 通用性且不包含具体内部信息，足以支持完整沉淀设计；具体文字、代码、Schema、测试和数据能否直接复用，仍由权属或许可决定；
- 内部基建依赖不是唯一风险，真实拓扑、私有平台行为、阈值、数据结论和专有实现表达也需要规避；
- 通用问题、状态机、步骤顺序、职责划分、模块排布和多个通用细节的组合可以完整保留，不要求为了区别来源而重排；
- 公开内容不得仅替换名称后复制受限文字、代码、Schema、测试或数据；这些表达和实现应自行编写或具有明确复用权；
- 发布前人工复核本版本新增和修改内容的来源、公开处理等级、权属、脱敏结果和排除项；不要求维护逐项仓外覆盖台账，实际存在的私有记录不得进入公开 Git；
- 敏感词扫描是发布门禁之一，不能替代内容、权属和保密义务复核。

## 公开处理等级

| 等级 | 公开深度 |
| --- | --- |
| `complete-solution` | 完整公开跨项目成立的问题、流程、状态机、职责、契约和验证方法 |
| `adapter-backed` | 完整公开通用流程与核心契约，采用方专有平台、环境或领域映射通过 Adapter 注入 |
| `problem-pattern` | 只在尚无稳定跨项目完整方案时公开问题、约束、失败模式和验证条件 |
| `exclude` | 内容本身仍含无法去除的内部事实，或具体表达/实现无法合法公开且无法自行编写，不进入公开仓库 |

分级只控制公开形态，不表示资产成熟度，也不规定必须怎样迁移或重写。具体文字、代码、Schema、测试与数据仍需自行编写或具有明确许可。维护者应在每次公开发布前对本版本新增和修改的公开资产作人工来源与权属复核，并对发现的问题完成排除、替换或降级处理。

## 决策顺序

1. 确认问题是否具有跨项目价值；
2. 判断问题、解决思路及其组合是否跨项目通用；
3. 区分可以保留的通用设计与需要自行编写或取得授权的具体表达和实现；
4. 排除内部标识、真实实例、真实拓扑、私有平台行为、权限、配置和数据；不以通用组合本身推定敏感；
5. 选择公开处理等级；
6. 在正式发布前完成人工权属与保密义务复核。

## 能力映射方式

公开资产不需要与任何来源仓库保持目录对应，可以按通用问题和采用边界选择：

| 方式 | 适用情况 |
| --- | --- |
| 一对一泛化 | 一个来源能力形成一个独立的通用能力 |
| 一对多拆分 | 一个能力分别形成 Framework、Skill、Template、Blueprint 或 Eval |
| 多对一合并 | 多个相似能力共用同一问题模型、契约或执行入口 |
| 横向抽取 | 从多个能力中提取 Evidence、Checkpoint、Adapter 等共享底座 |

映射方式不改变公开边界：通用方案可以保留，具体表达与实现仍需自行编写或具有明确复用权。

## 典型内容处理

| 来源内容 | 公开资产 |
| --- | --- |
| 内部平台调用 | Provider 或 Adapter 契约 |
| 真实生产案例 | 完全合成的场景、数据和失败条件 |
| 业务 Schema | 重新设计的最小通用 Schema |
| 固定阈值 | 有独立理由的可配置策略 |
| 平台特有失败 | 通用失败类别和验证条件 |
| 内部操作手册 | 安全状态机、职责边界和人工门禁 |

## 日志与遥测边界

- 默认关闭远端遥测，或只在本地保存必要结果；
- 不记录 Prompt、完整命令、工具原始输入输出、原始错误正文、邮箱或稳定个人标识；
- 远端上报必须显式开启，并公开字段清单、脱敏规则和保留周期；
- 日志和扫描结果只保留处理问题所需的最小信息，不回显仓外私有词表。
