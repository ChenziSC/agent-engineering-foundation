# Knowledge：通用能力的公开与独立重建

## 元信息

- ID：`public-generalization-policy`
- 状态：`current`
- 适用范围：能力盘点、公开分级、独立重建、发布检查
- 最后复核：`2026-08-05`
- 权威来源：脱敏与独立重写规范、迁移总览、公开内容来源说明

## 摘要

受限来源中的 Agent 能力全部进入非公开盘点，以保留其识别出的真实问题和工程价值。公开仓库不按来源过滤，而是根据公开依据、独立重建程度和权属状态决定交付深度。

## 稳定事实

- 通用性回答“是否值得沉淀”，不回答“是否有权公开”；
- 内部基建依赖不是唯一风险，非公开的独特方法组合、阈值、数据结论和实现也需要规避；
- 有充分公开依据且可以独立推导的能力，可以完整重建为 Skill、Blueprint 或参考实现；
- 公开内容不得以受限材料为底稿逐句、逐字段或逐结构改写；
- 私有覆盖台账用于保证全部能力得到处理，不能进入公开 Git；
- 敏感词扫描是发布门禁之一，不能替代内容、权属和保密义务复核。

## 公开处理等级

| 等级 | 公开深度 |
| --- | --- |
| `full-rebuild` | 完整重建设计与实现 |
| `design-rebuild` | 完整保留通用设计，表达和实现独立重建 |
| `framework-only` | 只公开问题、约束、原则、失败模式和扩展边界 |
| `exclude` | 不进入公开仓库 |

分级只控制公开形态。每项受限来源能力无论最终等级如何，都应在非公开覆盖台账中有明确处理结论。

## 决策顺序

1. 确认问题是否具有跨项目价值；
2. 查找解决思路的公开依据；
3. 判断是否能脱离原表达和原实现独立完成设计；
4. 排除内部依赖、真实实例和可反推内部结构的信息；
5. 选择公开处理等级；
6. 在正式发布前完成人工权属与保密义务复核。

## 刷新条件

- 公开处理等级或准入规则变化；
- 能力说明模板或覆盖台账字段变化；
- 发布前权属与敏感信息门禁变化；
- 新增可以改变既有能力公开等级的公开依据。
