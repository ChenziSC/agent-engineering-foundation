# Knowledge：通用能力的公开与脱敏复用

## 元信息

- ID：`public-generalization-policy`
- 状态：`current`
- 适用范围：能力盘点、公开分级、脱敏复用、表达与实现权属、发布检查
- 最后复核：`2026-08-05`
- 权威来源：公开化与权属规范、迁移总览、公开内容来源说明

## 摘要

受限来源中的 Agent 能力全部进入非公开盘点，以保留其识别出的真实问题和工程价值。公开仓库不按来源或通用细节的组合方式过滤，而是根据内容是否通用、是否已移除具体内部信息，以及表达与实现的权属状态决定交付深度。

## 稳定事实

- 通用性且不包含具体内部信息，足以支持完整沉淀设计；具体文字、代码、Schema、测试和数据能否直接复用，仍由权属或许可决定；
- 内部基建依赖不是唯一风险，真实拓扑、私有平台行为、阈值、数据结论和专有实现表达也需要规避；
- 通用问题、状态机、步骤顺序、职责划分、模块排布和多个通用细节的组合可以完整保留，不要求为了区别来源而重排；
- 公开内容不得仅替换名称后复制受限文字、代码、Schema、测试或数据；这些表达和实现应自行编写或具有明确复用权；
- 私有覆盖台账用于保证全部能力得到处理，不能进入公开 Git；
- 敏感词扫描是发布门禁之一，不能替代内容、权属和保密义务复核。

## 公开处理等级

| 等级 | 公开深度 |
| --- | --- |
| `complete-solution` | 完整公开跨项目成立的问题、流程、状态机、职责、契约和验证方法 |
| `adapter-backed` | 完整公开通用流程与核心契约，采用方专有平台、环境或领域映射通过 Adapter 注入 |
| `problem-pattern` | 只在尚无稳定跨项目完整方案时公开问题、约束、失败模式和验证条件 |
| `exclude` | 内容本身仍含无法去除的内部事实，或具体表达/实现无法合法公开且无法自行编写，不进入公开仓库 |

分级只控制公开形态，不表示资产成熟度，也不规定必须怎样迁移或重写。具体文字、代码、Schema、测试与数据仍需自行编写或具有明确许可。每项受限来源能力无论最终等级如何，都应在非公开覆盖台账中有明确处理结论。

## 决策顺序

1. 确认问题是否具有跨项目价值；
2. 判断问题、解决思路及其组合是否跨项目通用；
3. 区分可以保留的通用设计与需要自行编写或取得授权的具体表达和实现；
4. 排除内部标识、真实实例、真实拓扑、私有平台行为、权限、配置和数据；不以通用组合本身推定敏感；
5. 选择公开处理等级；
6. 在正式发布前完成人工权属与保密义务复核。

## 刷新条件

- 公开处理等级或准入规则变化；
- 能力说明模板或覆盖台账字段变化；
- 发布前权属与敏感信息门禁变化；
- 新增可以改变既有能力公开等级的内部信息、权属或许可证据。
