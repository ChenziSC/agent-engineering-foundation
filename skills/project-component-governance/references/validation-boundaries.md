# 验证与职责边界

## 职责

| Agent | 程序 | 人工 |
| --- | --- | --- |
| 理解需求与组件语义 | 解析目录、配置和导出 | 决定争议性抽象边界 |
| 比较候选和复用价值 | 检查契约、索引和链接 | 批准破坏性 API 变化 |
| 判断放置层级 | 扫描深路径和调用方 | 确认维护责任 |
| 设计迁移与废弃方案 | 运行构建、类型和测试 | 批准发布和大范围迁移 |

程序门禁只能证明结构满足规则，不能证明组件值得提升到标准层。

## 风险分级

| 类型 | 最低验证 |
| --- | --- |
| 纯展示、无状态 | 构建或类型检查 + Story/Demo |
| 格式化、计算、状态切换 | 单元测试 |
| 表单、焦点、键盘、异步交互 | 行为测试 |
| 高精度视觉或响应式布局 | 多状态 Story + 视觉验证 |
| 权限、请求或外部系统 | 合成 Adapter 测试 + 消费方验证 |
| 公开 API 迁移 | 调用方扫描 + 兼容测试 + 回滚检查 |

不要统一要求所有组件使用同一种测试，也不要用 Story 代替逻辑测试。

## 可确定性检查

项目可以按实际结构实现：

- 标准目录中的组件是否具备契约；
- 组件索引中的路径和契约是否存在；
- 公开组件是否从稳定入口导出；
- 是否出现禁止的深路径导入；
- 废弃组件是否声明替代项；
- 迁移后是否仍残留旧入口；
- 构建、类型检查和选定测试是否通过。

首版 Skill 不假设具体语言、目录或 Git Hook。仓库 Blueprint 决定如何接入。
