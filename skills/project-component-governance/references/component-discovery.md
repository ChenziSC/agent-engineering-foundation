# 组件发现

## 搜索顺序

1. 当前页面或模块已有组件；
2. 当前应用的公共组件；
3. 项目内共享组件与标准组件；
4. 已安装并实际使用的解决方案级组件；
5. 已安装的基础组件；
6. 前述来源均不满足时才考虑新建。

不要假设所有项目都使用 `components/`、`packages/ui/` 或某一种组件目录。先从仓库结构、Workspace 配置、包清单和导入关系识别真实来源。

## 候选证据

每个候选至少记录：

- 文件、文档或包入口；
- 公开导出方式；
- 核心交互与状态；
- 已知调用方；
- Story、Demo 或测试；
- 关键依赖与运行约束；
- 与本次需求的差异。

## 比较维度

| 维度 | 需要回答的问题 |
| --- | --- |
| 语义 | 组件解决的是同一个问题，还是只有视觉相似 |
| 状态 | 加载、空态、错误、禁用、只读等是否一致 |
| 交互 | 触发、校验、提交、键盘和焦点行为是否一致 |
| 数据 | 差异能否由适配器或外层转换解决 |
| 依赖 | 目标消费方能否安全加载样式、运行时和重依赖 |
| 扩展 | 插槽、组合或新增可选参数是否足够 |
| 兼容 | 扩展是否改变现有调用方的默认行为 |
