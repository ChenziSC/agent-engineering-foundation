# 输入与证据边界

## 必需输入

| 输入 | 最低要求 |
| --- | --- |
| 组件需求 | 能说明需要的主要交互、状态或维护动作 |
| 项目证据 | 可读取源码、组件契约、目录索引或公开文档中的至少一种 |

## 可选输入

- 设计稿、截图或交互说明；
- 目标页面、运行端和框架；
- 已知候选组件；
- 调用方和版本范围；
- 历史迁移、故障或重复建设记录。

## 证据优先级

1. 当前版本的组件源码、公开导出和测试；
2. 当前组件契约、Story、Demo 和组件索引；
3. 项目中的真实调用方；
4. 正式需求或设计说明；
5. 历史实现和讨论。

组件名称、目录名称、截图相似度和搜索结果摘要只能用于发现候选，不能单独证明可以复用。

## 范围固定

开始判断前记录：

- 仓库或工作区；
- 分支、提交或文件版本；
- 目标运行端；
- 本次需求覆盖的页面或模块；
- 可以读取和无法读取的组件来源。

如果组件文档与源码冲突，标记 `contract_conflict`。如果调用方行为与公开契约冲突，标记 `consumer_conflict`。不要自行忽略冲突。

## 降级

- 只有组件索引：可以给出候选清单，不能确认 API。
- 只有源码没有调用方：可以评估能力，不能承诺迁移影响面完整。
- 只有截图没有仓库：结果为 `blocked`。
- 仓库只能部分读取：结果至多为 `partial`，并列出未覆盖来源。
