# 常见失败模式

## 发现失败

- 只搜索共享组件包，忽略页面和应用内已有组件；
- 只按组件名检索，不按语义、状态和关键词检索；
- 看到截图相似就假设 API 一致；
- 找不到候选时不记录搜索范围，却声称项目中不存在。

## 决策失败

- 将轻量数据适配误判为新通用组件；
- 以“以后可能复用”为理由提前进入标准层；
- 发现近似组件后仍绕过扩展评估重新建设；
- 把业务流程、权限和请求编排封装成通用 UI；
- 将页面本地、应用共享和项目标准混成单一层级。

## 维护失败

- 只移动目录，不扫描深路径和样式依赖；
- 扩展公开组件却不检查现有调用方；
- 废弃组件没有替代项和迁移窗口；
- 组件索引、源码状态和文档各自维护不同事实；
- 用目录门禁代替语义准入评审。

## 修正原则

- 回到可验证的组件来源；
- 把事实、程序检查和 Agent 判断分开；
- 选择最小合理放置范围；
- 对未知调用方和运行条件显式降级；
- 将破坏性动作保留给人工确认。
