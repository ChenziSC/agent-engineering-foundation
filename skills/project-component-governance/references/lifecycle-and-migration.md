# 生命周期、迁移与废弃

## 生命周期

建议区分：

- `candidate`：只有候选或试验实现；
- `active`：当前可使用且有维护入口；
- `deprecated`：仍兼容，但不应新增调用；
- `retired`：已从公开入口移除；
- `migrating`：正在搬迁位置或替换实现，兼容尚未收口。

组件索引是状态与入口的唯一事实来源；源码注释、文档和发布说明引用该状态，不维护相互冲突的第二套状态。

## 历史组件迁移

迁移前必须：

1. 固定源组件和目标组件的版本；
2. 搜索公开导出、深路径引用和动态加载；
3. 比较 API、默认值、样式、状态和副作用；
4. 选择兼容导出、适配层或分阶段迁移；
5. 定义验证与回滚条件。

仅移动目录但不处理深路径、样式扫描和构建边界，不算完成迁移。

## 破坏性变更

以下变化默认视为潜在破坏：

- 删除或重命名公开参数；
- 改变默认值或受控/非受控模式；
- 改变错误、空态、加载和提交时机；
- 改变 DOM、焦点或键盘契约；
- 引入目标应用无法加载的样式或运行时；
- 将轻依赖替换为重依赖；
- 删除公开导出。

必须列出调用方影响和迁移窗口，不能只声明“组件内部重构”。

## 废弃

废弃记录至少包含：

- 废弃原因；
- 推荐替代项；
- API 映射；
- 已知调用方；
- 迁移期限；
- 兼容层；
- 删除条件；
- 回滚方式。

没有替代项或调用方扫描不完整时，可以标记 `deprecated`，但不得直接建议删除。
