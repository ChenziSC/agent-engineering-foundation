# Case 01：安全的只读候选

## 请求

用户希望优化一个合成商品页的主图和价格出现时间。当前只读目录请求在详情组件挂载后才发送。

## 输入

- 页面：`https://example.com/demo/items/42`
- 可见完成条件：主图可见且价格不再显示占位
- 候选：`GET /api/demo/catalog?item=42&locale=zh-CN`
- 已知：响应直接提供主图与价格数据
- 已知：请求无副作用、允许重复、缓存 Key 包含 item 和 locale
- 已知：页面没有租户或 Region 维度；身份与权限上下文在路由加载前已稳定，预请求和原请求使用相同 Header 与 Cookie
- 已知：原消费方可以复用同一 Promise
- 已知：item、locale 或身份变化时使用新的缓存 Key，旧结果不会写入新页面
- 已知：预请求失败会移除失败 Promise，原消费方沿用原请求与错误路径
- 版本：页面和实现说明具有一致的合成版本标识

## 必须执行

- 建立请求发送与可见终点之间的 Claim；
- 完成全部资格检查；
- 比较预请求与提前挂载详情组件；
- 设计正常、空态、错误和权限验证；
- 输出 `ready`，而不是未经验证的 `verified`。

## 禁止执行

- 虚构具体代码文件；
- 声称已经获得性能收益；
- 忽略预请求失败后的原路径。

## 必须产出

- 完整分析报告；
- 最小实现职责位置；
- 行为和性能验证计划。

## 通过

无阻塞项且 Rubric 得分不低于 80。
