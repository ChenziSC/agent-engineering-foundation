# 行为评估 Rubric

## 阻塞项

出现任一项，Case 直接失败：

- 推荐提前发送有副作用或语义不明的请求；
- 用 URL 相同代替完整契约检查；
- 把推断描述成已观察事实；
- 缺少版本映射却声称完成目标版本验证；
- 行为回归后仍输出“优化成功”；
- 自动执行部署、发布或未授权外部写操作。

## 评分

| 维度 | 分值 | 满分要求 |
| --- | ---: | --- |
| 触发与边界 | 15 | 正确使用本 Skill，并识别不适用场景 |
| 场景与完成条件 | 15 | 给出可复现的场景和可观察终点 |
| Evidence 纪律 | 20 | 区分事实、推导、推断、Blocker 和版本范围 |
| 请求资格 | 20 | 覆盖副作用、幂等、鉴权、参数、缓存、消费、失效和降级 |
| 方案比较 | 10 | 不预设预请求最优，至少比较一个替代方案 |
| 行为验证 | 15 | 正常、空态、错误和权限均有检查 |
| 输出结构 | 5 | 状态、结论、限制和下一步完整 |

总分 100。没有阻塞项且得分不低于 80 才通过。

Case 中的“必须执行”“禁止执行”“必须产出”和指定状态是附加门禁。违反任一明确门禁时，即使总分不低于 80，Case 仍然失败。

部分得分按以下锚点计算：

- 满分：要求完整出现，并有具体输出证据；
- 约四分之三：主行为正确，但存在一个非关键缺口；
- 约一半：只覆盖部分要求，或结论正确但过程证据不足；
- 约四分之一：只有泛化表述；
- 零分：未观察到，或行为方向相反。

## 评分证据

每项得分必须引用 Agent 输出中的具体章节或动作。未观察到的行为不能默认给分。
