## 9. 最小改造计划

1. 将空结果定义为预请求的合法完成状态，不得使用 truthy 判断区分“尚未完成”和“已完成但为空”。
2. 使用显式状态区分 `pending / success-with-data / success-empty / error`。
3. 保持原消费方的空态转换、文案和操作契约。
4. 仅在预请求错误、不可复用或超时时回退原请求路径；合法空结果不应被当成错误或继续 Loading。
5. 确保预请求与原消费方共享同一请求结果和缓存 Key，避免重复请求。
6. 未获得代码 Evidence 前，不指定具体文件或框架接入点。
