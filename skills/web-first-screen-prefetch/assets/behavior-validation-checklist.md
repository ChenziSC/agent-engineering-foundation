# 预请求行为验证清单

## 场景一致性

- [ ] 验证页面、入口和用户流程与分析场景一致。
- [ ] 登录、权限、语言和区域条件一致。
- [ ] 页面版本与代码版本关系已记录。
- [ ] 优化前后使用相同的缓存和网络策略。

## 请求契约

- [ ] 方法、URL、Query 和 Body 一致。
- [ ] Header、Cookie 和身份上下文一致。
- [ ] 缓存 Key 与消费方一致。
- [ ] 返回结构和数据转换一致。
- [ ] 失效规则明确。
- [ ] 没有新增重复请求。

## 正常场景

- [ ] 关键内容正确出现。
- [ ] Loading 状态正确结束。
- [ ] 原消费方复用了预请求结果。
- [ ] 可见完成条件可重复观察。

## 空态

- [ ] 空结果不会永久 Loading。
- [ ] 空态文案和操作保持正确。
- [ ] 空结果缓存不会污染其他场景。

## 错误

- [ ] 预请求失败不会阻断原路径。
- [ ] 重试行为符合原契约。
- [ ] 错误不会被误显示为空态或成功。
- [ ] 不发生无限重试。

## 权限

- [ ] 未授权场景不会提前访问受限资源。
- [ ] 权限变化后旧结果不会继续被消费。
- [ ] 权限错误保持原有处理方式。

## 导航与失效

- [ ] 快速切换路由不会消费旧页面结果。
- [ ] 参数变化会使用正确的新缓存 Key。
- [ ] 返回上一页时的数据策略符合预期。
- [ ] 重复进入不会触发有害重放。

## 性能结论

- [ ] 行为验证全部通过后才比较性能。
- [ ] 同时比较请求时间和用户可见终点。
- [ ] 不用单次最好结果代替稳定趋势。
- [ ] 没有版本映射时不使用 `verified`。

任一关键行为项失败时，最终结论不得为“优化成功”。
