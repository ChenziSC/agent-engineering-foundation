# 请求资格

## 判定结果

每个候选请求只能得到以下结果之一：

- `eligible`：当前 Evidence 足以支持进入方案设计；
- `conditional`：满足列出的条件后才可能使用；
- `blocked`：存在安全或契约阻塞；
- `unknown`：关键信息缺失。

`unknown` 不能被当作 `eligible`。

## 检查表

| 维度 | 必须回答 | 阻塞示例 |
| --- | --- | --- |
| 副作用 | 是否只读，是否改变服务器或用户状态 | 创建、提交、领取、确认、计数写入 |
| 幂等 | 重复发送是否产生不同结果或额外影响 | 一次性 Token、重复扣减、重复记录 |
| 鉴权 | 提前发送时是否具备相同身份和权限上下文 | 会话尚未建立、权限信息稍后注入 |
| 参数 | 参数是否在提前发送时已经稳定 | 地区、语言、用户选择尚未确定 |
| 缓存 Key | 提前请求和消费方是否命中同一条缓存记录 | Header、Query、Body 或环境字段不同 |
| 消费契约 | 原消费方能否复用提前返回的数据 | 返回结构、转换逻辑或错误模型不同 |
| 失效 | 数据何时过期，导航或上下文变化后如何处理 | 用户切换导致旧结果仍被消费 |
| 降级 | 预请求失败时是否回到原请求路径 | 失败后永久停留在加载态 |

## 默认拒绝

默认拒绝：

- POST、PUT、PATCH、DELETE 等可能写入的请求；
- 名称看似只读但无法确认服务端行为的请求；
- 创建会话、领取资源、上报埋点、确认状态等动作；
- 包含一次性签名、随机数或不可重放凭证的请求；
- 需要在用户明确操作后才能获得授权的请求。

HTTP 方法只能作为线索，不能替代业务语义判断。

## URL 相同不代表契约相同

比较完整请求语义：

- 方法；
- URL；
- Query；
- Body；
- Header；
- Cookie 或身份上下文；
- Locale、Region、租户等范围；
- 错误和重试策略；
- 缓存与数据转换。

只要消费方无法证明会复用同一个结果，就不能声称预请求消除了重复请求。

## 条件性资格

以下场景可以标为 `conditional`：

- 参数将在一个明确阶段后稳定；
- 权限上下文可以在路由进入前完成；
- 消费方需要小范围改造才能共享请求结果；
- 预请求只在特定路由或特定用户状态启用；
- 必须增加显式失效或回退规则。

条件必须进入实现计划和验证清单，不能只写在备注中。
