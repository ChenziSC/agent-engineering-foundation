# 安全变更

## 目标

让“修改已完成”与“声明范围内的风险已验证”分开可见，避免只凭测试命令退出码或单个正常路径宣布安全。

## 工作流

1. 确认候选版本、目标、非目标和允许修改的路径。
2. 收集变化路径及直接消费者，按行为、契约、数据、权限、性能和可逆性分类风险。
3. 为每类路径建立覆盖规则，引用自动检查、浏览器场景和人工门禁。
4. 正常、空态、错误、权限、加载与恢复场景按实际风险选择，不机械要求所有场景。
5. 先执行低成本确定性检查，再执行受影响场景；结果必须引用版本一致的 Evidence。
6. 记录未覆盖路径、失败结果、未知外部状态和回滚条件。
7. 只有覆盖矩阵全部完成才输出 `validated`；否则输出 `partial` 或 `blocked`。

## 必须遵守

- 不把“未观察到错误”写成“没有风险”。
- 不自动执行提交、推送、发布、数据迁移或不可逆外部操作。
- 不用路径筛选隐藏候选中的其他变化。
- 浏览器证据必须记录候选版本、前置条件、动作和期望。
- 使用项目内 `frameworks/change-validation/` 的确定性矩阵时，以其输出为结构证据，不把它当作业务正确性证明。
