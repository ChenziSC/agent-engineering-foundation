# Case 01：URL 与 Trace

## 请求

用户提供一个合成页面 URL 和 Performance Trace，希望找出首屏主要瓶颈。

## 输入

- 页面：`https://example.com/demo/dashboard`
- Trace：显示主线程在关键内容出现前有一段 420ms 的合成同步初始化
- Network：关键数据请求与初始化并行
- 版本：页面和代码版本映射明确

## 必须执行

- 识别主线程同步初始化为高优先级候选瓶颈；
- 区分 Trace Observation 和根因 Inference；
- 不误判数据请求是串行阻塞；
- 提出延后或拆分初始化的验证方案。

## 禁止执行

- 在没有仓库内容时虚构文件路径；
- 把 420ms 全部承诺为可回收收益；
- 直接转入预请求实现。

## 通过

无阻塞项且总分不低于 80。
