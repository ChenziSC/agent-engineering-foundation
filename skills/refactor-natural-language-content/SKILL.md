# 自然语言工程内容一致性重构

## 目标

识别多轮局部修改造成的整体语义和结构问题，在保留真实意图、权威来源和有效信息的前提下，审计或重构自然语言工程内容。默认使用中文分析和交付；代码标识符、格式固有字段和通行术语可以保留英文。

## 先执行范围门禁

仅处理以自然语言为主要载体的工程内容，包括 Spec、Plan、Skill、Prompt、规范、流程、评估标准、模板说明和仓库治理指令。

先判断主要操作对象，再解释“重构”“整理”“统一”等动作词。动作词本身不能改变对象范围；“重构代码实现”“整理测试结构”等请求仍然是代码任务，不触发本 Skill。

遇到以下情况时不要触发全文扫描或重构：

- 修改业务代码、测试、脚本、依赖、锁文件或普通配置；
- 修正孤立错别字、格式或不改变含义的局部表达；
- 一般文章润色、营销文案、翻译或创意写作；
- 仅因文件中存在注释、错误消息或短字符串而把代码当作自然语言文档。

代码中的 Prompt 或长规则文本只有在自然语言内容本身是用户的主要操作对象时才纳入；不要借此扫描或重构周边代码。

## 区分审计与重构

- 仅当主要操作对象已经通过上述范围门禁时，用户明确要求对这些内容“整体整理”“重构”“去重”“统一术语”“解决冲突”或执行等价动作，才进入 `refactor`，并且只能修改用户指定范围内的内容。
- 因高风险信号隐式触发时，进入 `audit`，只读检查并报告问题；不要扩大原请求的写入范围。
- 用户只要求局部修改时，保持局部修改。发现远端问题可以提示并给出建议，不要顺手改写全文。
- 用户要求检查但没有要求修改时，只输出审计结果和候选方案。

## 使用低成本影响门禁

根据用户请求、当前差异和已经读取的上下文判断影响，不为判断风险额外重读全文，也不要在无风险时输出一份形式化风险报告。

按风险逐级扩大范围：

| 级别 | 典型变化 | 默认检查范围 |
| --- | --- | --- |
| 低 | 错别字、格式、局部无语义润色 | 当前段落和直接上下文 |
| 中 | 修改单条需求、步骤或局部规则 | 当前章节和直接引用 |
| 高 | 修改公共定义、规范性规则、优先级、公共字段或章节结构 | 定向搜索后按命中决定全文或多文件扫描 |

出现任一信号时，至少执行定向搜索：

- 新增或修改“必须、不得、默认、优先、唯一”等规范性规则；
- 修改公共术语、输入输出契约、模板字段或稳定标识；
- 重命名、移动、删除、拆分或合并章节与概念；
- 一次变更跨越多个章节或文件；
- 已发现冲突、语义重复、术语漂移或失效引用；
- 自上次一致性检查后，同一内容发生多次可观察的语义修改。

同一轮连续修改应合并检查。先搜索相关概念、标题、规则 ID 和引用；只有候选命中显示问题可能跨越全文，或用户明确要求完整审计时，才读取全文。详细决策和退出条件见 [workflow.md](references/workflow.md)。

## 执行工作流

1. 确认目标文件、授权范围、用户目标和已知权威来源；不要把当前章节位置自动当成权威等级。
2. 记录实际可见的修改和风险信号。无法观察历史修改次数时，不要假装知道内容已经修改了多少轮。
3. 使用搜索工具收集候选段落，再按需读取直接引用、同名章节和定义位置。
4. 将问题分类为：规则冲突、语义重复、术语漂移、结构碎片、引用失效或权威不明。不要把措辞差异直接认定为冲突。
5. 在 `audit` 中报告证据、影响和建议；在 `refactor` 中先确定权威表达和目标结构，再执行范围内修改。
6. 保留有明确用途的摘要、示例和面向不同读者的解释；合并语义重复时保留唯一权威正文，并修正引用。
7. 重构后重新搜索旧术语、旧规则、失效标题和残留引用，核对是否引入新的冲突或遗漏。
8. 报告实际检查范围、已解决问题、未解决问题和需要人工决定的冲突，不把局部搜索描述成全文审计。

## 硬性门禁

- 不因隐式触发执行超出原请求范围的写入。
- 不在权威来源不明时静默选择一条冲突规则。
- 不把有意摘要、示例和分层说明机械判为重复并删除。
- 不用统一措辞掩盖事实差异、版本差异或适用范围差异。
- 不修改没有证据支持的事实、阈值、权限、安全规则和完成条件。
- 不把普通代码修改解释为自然语言内容重构请求。
- 不声称扫描了未实际读取或搜索的范围。
- 不为目录完整新增脚本、资产或报告文件；只有实际任务需要时才创建产物。

常见误用及修正方式见 [failure-modes.md](references/failure-modes.md)。

## 输出要求

只读审计至少说明：

- 实际检查范围与使用的证据；
- 问题类型、位置、影响和建议；
- 是否存在权威不明或需要授权的改写。

完成重构后至少说明：

- 修改了哪些内容和结构；
- 合并、保留或未处理了哪些冲突与重复；
- 执行了哪些复查；
- 哪些结论仍未验证。

事实、程序搜索结果和 Agent 推断必须分层表达。没有发现问题时简洁说明检查范围即可，不输出冗长空报告。
