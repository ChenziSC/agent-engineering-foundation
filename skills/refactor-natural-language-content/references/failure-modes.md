# 常见失败模式

## 每次修改都扫描全文

问题：把风险判断实现成完整复读，使低风险编辑也付出与文档规模线性相关的成本。

修正：只依据请求和差异执行增量门禁；先定向搜索，命中跨范围风险后再扩大扫描。

## 只看当前段落

问题：公共定义、规范性规则或标题变化后，没有检查远端引用。

修正：命中高风险信号时搜索旧词、新词、规则 ID、标题和引用，再读取候选上下文。

## 隐式触发后顺手重构

问题：Agent 把主动发现问题等同于获得扩大写入范围的授权。

修正：隐式触发保持 `audit`；报告问题和候选方案，等待用户明确授权。

## 把所有重复都删除

问题：摘要、示例、局部提醒或不同受众说明被当作冗余，导致内容难用或信息丢失。

修正：判断重复承担的职责。保留有明确用途的表达，使其引用唯一权威正文。

## 用措辞统一掩盖事实冲突

问题：不同版本、范围或阈值被改成相同句式，看起来一致但真实差异消失。

修正：先核对适用范围和证据；权威不明时保留冲突并请求决策。

## 把代码改动当作内容重构

问题：看到“重构”一词或代码中的注释、字符串就加载全文内容审计。

修正：按主要操作对象判断。普通源代码、测试和配置修改退出本 Skill；只有 Prompt 或长规则文本本身是目标时才处理该文本。

## 声称完成未执行的扫描

问题：只搜索了几个关键词，却声称全文没有冲突。

修正：明确区分已读取范围、搜索命中和 Agent 推断；没有全文证据时只报告候选范围内结论。

## 为结果整齐而扩大重写

问题：已确认问题很小，但 Agent 为统一文风重写无关章节，制造大范围差异。

修正：选择能解决已确认问题的最小结构调整；无关风格优化另行请求和授权。
