# 分层扫描与重构工作流

## 1. 固定范围与权限

先回答四个问题：

1. 主要操作对象是否为自然语言工程内容；
2. 用户要求的是局部修改、只读审计还是整体重构；
3. 哪些文件或章节在授权范围内；
4. 是否存在明确的权威来源、版本或优先级。

如果主要对象是普通代码，退出本 Skill。如果用户没有授权扩大改写，后续即使发现问题也只报告。

## 2. 执行增量影响判断

只使用当前请求、当前差异和已经读取的上下文，不先阅读全文。

### 低风险快路径

以下条件全部成立时，只检查当前段落和直接上下文：

- 修改不改变规则、事实和完成条件；
- 不涉及公共术语、字段、标题或稳定标识；
- 没有移动、删除、拆分或合并；
- 没有观察到其他位置使用同一概念；
- 用户没有要求整体检查。

### 定向搜索路径

存在高风险信号时，优先使用 `rg` 或宿主等价搜索能力定位：

- 旧术语与新术语；
- 规范性关键词及目标规则；
- 标题、锚点、规则 ID、字段名和稳定标识；
- “见某节”“遵循某规则”等显式引用；
- 相同或近似的职责陈述。

搜索只负责确定候选位置。语义重复和冲突必须由 Agent 读取候选上下文后判断。

### 全文或多文件扫描路径

满足任一条件时扩大扫描：

- 用户明确要求完整审计或整体重构；
- 公共定义、契约或规范性规则在多个章节出现；
- 结构操作使引用关系无法通过少量候选闭合；
- 已确认至少一处跨章节冲突或术语漂移；
- 同一轮修改涉及多个相互依赖文件；
- 定向搜索无法判断唯一权威正文。

同一轮连续修改只在最后执行一次合并扫描。后续只有再次修改公共定义、规范规则或结构时，才使扫描结果失效。

## 3. 建立问题清单

按以下类型分类，避免用“内容不一致”笼统概括：

| 类型 | 判定要点 | 默认动作 |
| --- | --- | --- |
| 规则冲突 | 同一适用范围给出不能同时成立的要求 | 查明权威；不明时请求决策 |
| 语义重复 | 多处承担相同权威职责，维护时可能漂移 | 合并权威正文并保留必要引用 |
| 术语漂移 | 同一概念使用不同名称，或同名概念含义变化 | 选择规范术语并检查全部引用 |
| 结构碎片 | 一个主题的前提、规则和例外散落，难以整体理解 | 按读者任务重组并保留可追溯入口 |
| 引用失效 | 标题、锚点、编号或文件关系不再成立 | 更新引用并复查反向引用 |
| 权威不明 | 多个来源无法从证据判断优先级 | 保留冲突，列出需要人工决定的问题 |

重复出现不等于语义重复。摘要、索引、示例、局部提醒和面向不同受众的解释可以合理存在，但应指向唯一权威规则，避免各自承担状态所有权。

## 4. 设计目标结构

进入 `refactor` 后，先确定：

- 每个主题的唯一权威位置；
- 定义、规则、例外、示例和引用的顺序；
- 需要保留的兼容术语与迁移说明；
- 不能自动决定的冲突和事实缺口。

优先进行能解决已确认问题的最小结构调整。不要为了形式统一重写无关章节，也不要把所有短章节强行合并。

## 5. 执行与复查

修改后至少执行：

1. 搜索旧术语、旧标题、旧规则 ID 和被删除字段；
2. 检查权威正文与摘要、示例、模板之间是否一致；
3. 检查规范性要求、例外和优先级是否仍能同时成立；
4. 检查链接、锚点和跨文件引用；
5. 比较修改前后的目标、非目标和完成条件，确认没有无证据改变意图；
6. 记录未解决冲突、未扫描范围和需要人工确认的事实。

## 6. 退出条件

只读审计在以下条件成立时结束：候选范围已说明，问题有证据或明确标为推断，所有写入都保持未执行。

重构在以下条件成立时结束：授权范围内的问题已处理或明确保留，旧引用已复查，没有把权威不明问题伪装成已解决，并如实报告实际扫描范围。
