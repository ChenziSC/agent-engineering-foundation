## Case 01

### T01-A

**实际决策、边界与产出**

- 事实：
  - 详情组件可能因数据重试重新挂载。
  - 目标口径是同一页面访问中的首次有效可见。
  - 每次渲染或挂载均触发不符合需求。

- 设计产出：
  - Event：`item_first_effectively_visible`
  - 目的：统计每次页面访问中条目的首次有效曝光，不统计渲染次数。
  - 精确触发草案：有效数据加载完成后，条目可视面积达到 50% 并持续 1 秒时触发；同一页面访问和条目只允许一次。
  - 页面访问边界：进入目标路由开始；离开路由或整页刷新结束。重新进入属于新的访问。
  - 去重：在页面访问作用域维护 `pageVisitToken + internalItemKey` 集合；先原子检查并登记，再调用 Adapter。重挂载复用访问级状态。
  - 数据最小化：去重键仅保存在客户端访问周期内，不作为事件属性上传。
  - 属性契约草案：

    | 属性 | 类型 | 来源 | 必填 | 隐私 |
    | --- | --- | --- | --- | --- |
    | `schema_version` | string | Event Catalog 常量 | 是 | 非个人数据 |
    | `item_type` | enum | 已成功加载的数据模型 | 是 | 分类待项目确认 |
    | `entry_source` | enum | 规范化路由入口 | 是 | 使用数据，分类待确认 |

  - 缺少必填属性时不使用默认值掩盖，不发送事件。
  - 候选代码落点：成功绑定有效数据后的可见性观察边界。
  - 该落点属于推断；未读取真实业务代码，不能声称已定位具体文件。
  - Adapter：仅规划由项目 Adapter 注入，未绑定或调用真实 SDK。
  - 状态：`draft / pending-confirmation`。

- 验证场景：
  - 首次满足有效可见条件时恰好触发一次。
  - 数据重试及组件重复挂载后不重复触发。
  - 短暂可见但未达到持续时间时不触发。
  - 首次不可见、重试后有效可见时触发一次。
  - 离开并重新进入页面后允许新访问触发一次。
  - 缺失必填属性、加载失败或取消时不触发。
  - Event Catalog 与代码使用相同 `schema_version`。
