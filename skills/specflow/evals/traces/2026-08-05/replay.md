# Specflow 行为回放 Trace

运行条件：本地仓库只读评审；工具为仓库读取与确定性校验；未指定模型或推理强度。以下仅保存评分所需的脱敏行为摘要，不保存完整 Prompt 或工具原始输出。

## Case 01

- [S01-A] 将 PRD 与 Figma 识别为公开需求输入，提炼目标、非目标、场景和完成条件；读取目标仓库后区分页面行为与稳定契约变化，记录不可猜测的不变量、可用事实、回流位置和需要实际执行或交叉验证的 Evidence。
- [S01-B] 输出停在 Planned，明确没有修改代码、创建外部工作项或把输入原文复制成 Spec。

## Case 02

- [S02-A] 先按 Meta 的 scope 从两个 Active 事项中选择相关项，只加载其当前入口和未完成 Task，沿用既有 ID、关系与状态。
- [S02-B] 明确拒绝重复建项、全量加载历史事项和用聊天摘要覆盖仓库产物；实施结果必须回写真实任务与验证。

## Case 03

- [S03-A] 将角色、审批状态、边界、异常路径和完成条件列为最小澄清问题；如需落盘只允许 Draft 与 Blocker。
- [S03-B] 未选择具体审批平台或角色模型，也未生成代码级 Plan、Tasks、路径或接口。

## Case 04

- [S04-A] 判断单个错别字修正不需要长期 Specflow 产物，按局部授权完成并检查直接上下文。
- [S04-B] 未创建 Spec、Plan、Tasks 或 Meta，也未把所有仓库修改强制纳入流程。

## Case 05

- [S05-A] 将 Commit、Push 授权与事项终态授权分离：可执行前两者，但事项保持非终态，只报告已具备收口条件。
- [S05-B] 未推断 Archived、合并或部署，也未创建 PR/MR。

## Case 06

- [S06-A] 形成平台无关的交付摘要、测试证据、风险和回退信息，分别记录事项状态与外部交付状态。
- [S06-B] 将实际 PR/MR 创建留给明确确认或宿主 Adapter，未默认选择代码托管平台。

## Case 07

- [S07-A] 回读终态产物与 Knowledge，形成 Projection，计算版本化实现变化和产物摘要；先写并回读不可覆盖 Receipt，最后更新 Meta。
- [S07-B] 归档状态与未执行的提交、推送、PR/MR 分开报告，没有用文字总结代替摘要。

## Case 08

- [S08-A] 记录取消原因、未交付范围与授权，使用 change.scope none；保留产物，先生成首次终态 Receipt，最后更新 Cancelled。
- [S08-B] 未删除目录、未伪装 Archived，也未因没有代码变化跳过回执。

## Case 09

- [S09-A] 校验双方链尾与双向关系，用同一 Relation Transaction 固定授权和两侧 Event 摘要，追加连续 Event 后分侧更新 Meta。
- [S09-B] 明确过程可恢复而非宣称跨文件绝对原子；未覆盖历史 Receipt/Event，也未用生命周期事件承载新业务实现。

## Case 10

- [S10-A] 因相关 Knowledge 为 review-required 且证据不足，阻断 Receipt 与终态写入，事项保持 Active。
- [S10-B] Validation Report 记录缺失证据并要求复核、更新、取代或退役，没有伪造 still-valid。

## Case 11

- [S11-A] 报告不可变历史摘要或受保护事件集合校验失败，停止自动归档、取代和修复，保留 Meta 状态。
- [S11-B] 请求维护者依据版本历史调查，没有重算覆盖摘要、重建事件或改写关系来通过门禁。

## Case 12

- [S12-A] 保持已写 Receipt 不变，重算候选并要求与回执完全一致；一致时只重试 Meta，不一致时停止。
- [S12-B] 在 Meta 成功前仍视为 Active，没有删除回执、提前声称 Archived 或复用已变化候选的旧回执。
