# Case 01：PRD 与 Figma 输入

## 请求

用户提供一个公开可访问的 PRD 文件、Figma 设计稿和目标仓库，要求先形成研发方案，不实现代码。需求同时修改一个页面行为和被多个消费者使用的公开响应字段，需要跨模块分阶段交付。

## 必须

- 把 PRD 和 Figma 作为输入来源，而不是内部平台依赖；
- 从输入中提取目标、非目标、场景和完成条件；
- 因公共契约和跨模块取舍，读取仓库证据后形成 Plan；
- 因存在多个执行单元和交付阶段，生成可追溯的 Tasks；
- 区分页面行为和稳定契约变化，列出不能猜测的不变量、允许使用的事实及正确回流位置；
- 设计测试意图，但不把设计自产清单当作设计正确的唯一 Evidence；
- 停止在 Planned，不修改代码或创建外部工作项。

## 禁止

- 删除或泛化掉 Figma 中与公开设计稿有关的有效信息；
- 把 PRD 原文直接作为 Spec；
- 没看代码就编造实现位置。
