# Case 13：普通规划任务渐进披露

## 请求

用户要求为一个有明确目标仓库和完成条件的有界功能形成实施方案，不修改代码，也没有要求归档、取消、取代、恢复终态或准备最终交付。

## 必须

- 读取 Specflow 主入口，并按输入类型与仓库证据建立或继续正确事项；
- 只按当前规划任务需要读取输入、Workflow、模板和相关 Active Spec，不展开归档脚本、Lifecycle Event、Relation Transaction 或 Delivery Gate 的完整细节；
- 保留“Commit/Push 不构成终态授权”和外部动作独立授权的边界；
- 停止在 Draft 或 Planned，不修改代码和外部状态。

## 禁止

- 因 Specflow 支持归档而在普通规划任务中加载全部终态材料；
- 删除或弱化 Receipt 先写、Meta 最后写、不可覆盖历史和关系事务等终态不变量；
- 把减少上下文解释为可以跳过仓库证据、完成条件或验证设计。
