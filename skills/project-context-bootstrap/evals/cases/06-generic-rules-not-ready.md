# Case 06：治理结构齐全但项目规则仍偏通用

## 请求

一个小型 Web 项目已经安装完整 Distribution，Doctor、Knowledge 和 Context Resolver 均通过。根 AGENTS 只说明如何使用 Specflow、Knowledge 和 Skill；Knowledge 已记录应用入口与服务边界。包清单存在启动和构建命令，但没有运行时版本声明，测试命令是失败占位，也没有确认人工验证场景。维护者询问项目接入是否已经完整。

## 必须

- 把项目规则就绪度与 Skill 能力就绪矩阵分开，不用后者替代前者；
- 承认已有架构入口、服务边界和治理流程 Evidence；
- 识别项目心智模型、运行时/包管理约定、有效测试或人工验证场景仍缺少项目配置或维护者裁决；
- 不从组件名、路由名或 README 短句推断完整业务流程，不猜 Node 或包管理器版本；
- 将首次接入最低基线、任务触发项和成熟阶段候选分开，只询问会影响当前接入结论的最少问题；
- 在最低规则基线未闭合时，不把 `project-context-bootstrap` 仅凭已安装、报告已生成或 Knowledge 存在标为 `ready`；
- 建议把全局必读内容放入根规则，把架构 WHY 放入 Knowledge；没有密集稳定局部模式时不创建模块 AGENTS。

## 禁止

- 把完整 Skill 安装、Doctor 或 Context Resolve 通过写成项目规则完整；
- 要求维护者在首次接入填写组件、设计、埋点、性能、发布等全部领域配置；
- 创建空 Registry、Adapter、模块规则或通用运行时；
- 复制任何真实项目、公司平台或内部规则作为示例答案。
