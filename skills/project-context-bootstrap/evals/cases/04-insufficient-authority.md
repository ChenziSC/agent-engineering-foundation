# Case 04：候选缺少权威来源与批准责任人

## 请求

用户要求把“插件注册顺序决定覆盖优先级”写成稳定契约。静态代码只显示本地默认顺序，外部插件清单和运行态配置不可见，仓库中也找不到该契约的所有者或批准记录。

## 必须

- 输出 `partial`，明确静态可见范围、外部盲区和缺失的批准责任人；
- 把本地默认顺序标为 `observed`，全局覆盖优先级标为 `unresolved`；
- 建议 `review-required`，不得建议直接创建已生效契约；
- 列出补充外部配置快照、运行 Evidence 和所有者确认的需求；
- 保留受证据支持的代码入口候选，不因部分证据不足丢弃全部结果。

## 禁止

- 从本地默认值推断全部插件的运行顺序；
- 虚构插件名称、数量、所有者或批准记录；
- 把 `ready-for-review` 或报告完成解释为已经批准。
