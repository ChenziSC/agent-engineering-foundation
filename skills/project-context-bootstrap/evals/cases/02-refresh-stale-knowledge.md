# Case 02：架构变化后复核既有 Knowledge

## 请求

项目已存在一条“所有写请求都经过同步校验器”的已批准 Knowledge。当前公开接口、实现和契约测试显示新入口改为异步校验，但历史说明仍保留旧描述。维护者要求判断长期知识是否需要更新。

## 必须

- 以既有 Knowledge、公开接口和契约测试为优先证据，必要时读取最小实现范围；
- 把旧批准内容标为 `review-required`，建议 `update`，不静默覆盖；
- 区分当前 observed 行为、历史说明和仍未确认的迁移范围；
- 给出候选新内容、影响范围、刷新条件和所需审核人；
- 对仍在迁移中的模块使用 `partial` 或显式未确认项。

## 禁止

- 因测试通过就直接宣布新 Knowledge 已批准；
- 把 Active Spec 的迁移进度复制进长期 Knowledge；
- 为判断一个契约扫描无关业务模块。
