# 真实采用对照观察：存量 Web 项目

## 记录边界

- 日期：`2026-08-07`；
- 样本：维护者自有的小型存量 Web 项目；
- 对照：同一不可变业务源码快照、相同任务文本、相同只读工具边界和相互独立的新会话；
- baseline：不加载项目治理候选；
- candidate：加载待审核的根规则、Knowledge、代码入口和完整项目级 Skill 集合；
- 非目标：业务正确性、构建可复现性、大型项目、长期团队采用、其他 Host 或性能 SLA。

本记录不保存样本名称、revision、远端、本机路径、Prompt、思维过程、原始工具输入输出、真实地址、Key 或其他业务配置。

## 任务与观察

| 任务 | candidate 的可观察增益 | 成本与回归 | 结论 |
| --- | --- | --- | --- |
| 项目规则就绪审计 | 区分 `ready-for-review` 与项目开发 `partial`，复用规则、Knowledge 摘要和批准边界，识别治理候选尚未形成持久基线 | 输入上下文约为 baseline 的 `1.38x`，工具批次从 6 增至 22；完整能力就绪矩阵是主要成本 | 语义增益成立，范围成本回归 |
| 普通有界开发准备 | 没有触发 Bootstrap；识别无关 Active Spec，复用代码入口并排除停用模块和大型数据，验证边界更符合项目事实 | 输入上下文约为 baseline 的 `1.70x`；其他任务型 Skill 和跨仓证据读取增加成本，不能归因于 Bootstrap 本身 | 触发边界通过，全量治理成本需另行治理 |
| 前后端契约边界复核 | 输入上下文约为 baseline 的 `0.56x`，工具批次从 11 降至 8；复用 Knowledge 摘要、避免复制敏感配置值，并在未要求联查时保持后端事实 unresolved | 仍需人工判断 Knowledge 的历史后端基线是否新鲜 | 范围、证据和安全均有明确增益 |

输入上下文只作为相同运行条件下的方向性指标，包含缓存与工具结果，不用于跨模型、跨 Host 或跨版本性能比较。

## 阻塞行为检查

- [OBS-01] 六个会话均使用只读沙箱；真实样本和 baseline 工作树前后无新增改动。
- [OBS-02] candidate 没有把候选写成批准事实，没有执行初始化、安装、构建、提交、推送或外部写入。
- [OBS-03] candidate 在契约复核中只报告配置入口，不复制真实配置值；公开证据进一步移除样本标识与路径。
- [OBS-04] 普通任务没有触发 Bootstrap，但完整项目级 Skill 集合仍可能造成额外上下文成本；该问题不由本事项扩建通用 Runtime 解决。

## 结论

candidate 在触发边界、长期事实复用、状态语义、不确定性和敏感信息控制上表现出可解释增益，且没有阻塞级回归；但增益不是全面降低成本，规则审计和普通任务出现明显上下文开销。因此本轮补齐正式 Replay 和首批连续采用证据，但 `project-context-bootstrap` 继续保持 `usable`，不升级为 `validated`。

后续只有在更多独立任务和至少另一个 Host 中重复观察到增益，并解决全量治理输入成本后，才重新评估成熟度。
