# 项目上下文引导与任务切片自评 Trace

运行条件：当前会话前向执行；工具为仓库读取、确定性命令与本地测试；未指定模型或推理强度。以下只保存完成评分所需的脱敏行为摘要，不保存完整 Prompt、工具原始输出、私有仓库名称、真实业务名称、内部平台、人员、链接或绝对路径。

本 Trace 是同一 Agent 的 `self-review`，不是独立评审。对应 Replay 使用非正式文件名 `replay.self.json`，不能据此把 Skill 标记为 `validated`。

## Case 01：存量项目最小 Bootstrap

- [C01-A] 在临时合成项目中选择 `bootstrap`，范围限定为目录模块；读取根级与模块级规则、公开 Schema、模块出口和邻近测试。报告将项目规则、稳定契约候选、动态锚点和未确认项分层，显式保留“旧架构说明与当前 Schema 冲突”，稳定契约保持 `draft`，并以合成快照摘要 `b4248cebdf66e49578f771cb148d7b1b9f1eb3ef8d88936903c9f0ed94e94b8a` 绑定结果。
- [C01-B] 达到目录模块接入目标后停止，明确排除库存与推荐模块；没有修改被评估项目的产品代码、写入 Knowledge、提交、推送或发布。由于文档冲突和运行态消费者仍待确认，输出状态为 `partial`。

## Case 02：消费 Section Index

- [C02-F] 首次尝试把 Resolver 与包含 Active Spec 正文的广泛搜索并行执行，违反“先解析、再按索引选节”的顺序门禁。该次结果未计为通过；随后补强 Skill、工作流 Reference、Rubric 和本 Case 的明确约束。
- [C02-A] 修正后的重跑严格按“等待 Resolver 返回 → 查看 Section Index → 选择完成条件、兼容与迁移、数据流和相关未完成 Task → 仅按行区间读取原文”执行。未选择的 UI 细节没有读取，也没有把索引标题当作语义摘要。
- [C02-B] 最终重跑未全文读取大型 Spec、未对其核心文档执行并行广泛搜索，也未在 Skill 内重新实现 Markdown 分段或预算算法；进入 `slice` 后只围绕缓存兼容目标建立上下文。

## Case 03：有边界的任务切片

- [C03-A] 选择 `slice`，从合成目录路由和加载函数定位真实定义，形成“路由 → 加载 → 服务 → 价格格式化 → 页面/购物车预览”的直接调用路径，以及“响应价格字段 → 格式化 → 文本或不可用降级 → 消费者”的关键数据链；同时纳入公开 Schema、异常降级和两类邻近测试。
- [C03-B] 报告记录候选快照、目标路径、非目标和停止边界；没有递归扩展无关模块，没有把搜索命中文件清单冒充关系图，也没有把当前调用链提升为长期 Knowledge。

## Case 04：动态消费者尚未闭合

- [C04-A] 静态证据确认两个本地直接消费者并标记为 `observed`；对运行时 Registry 可能存在的插件消费者标记为 `unresolved`，输出 `partial`，建议补充 Registry 快照、运行 Trace 或 Adapter Evidence，同时保留已证实的有限切片。
- [C04-B] 未根据静态搜索断言消费者集合完整，未虚构插件名称、数量或调用关系，也没有因运行态证据不足而丢弃已观察事实。

## 本仓自举检查

- [SELF-A] 先运行 Context Resolver。本仓父事项因体量被标记为 `sectioned`，只按 Section Index 读取与分发、Eval 和验证有关的局部章节；当前事项按加载计划读取。随后围绕 Skill 目录、分发清单、能力说明、Knowledge 路由和当前 Spec 建立直接消费关系。

- [PRIVATE-F] 首次进入私有参考仓库时先做了定位检索，晚于该仓要求的只读 Context Bootstrap。该过程偏差被保留为限制，不计作完全合规的首次接入回放。
