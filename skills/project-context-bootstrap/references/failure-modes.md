# 失败模式

| 失败模式 | 问题 | 修正 |
| --- | --- | --- |
| 把切片理解为固定大小分块 | 字节边界不能表达任务语义 | 以入口、符号和数据元素为锚点，字节预算只负责加载保护 |
| 跳过 Section Index 重读大型 Spec | 浪费上下文并复制已有能力 | 先用索引定位，再读取相关章节原文 |
| 只列文件，不说明关系 | 不能支持实现或验证决策 | 给出入口、调用、数据、消费者、异常和测试之间的关系 |
| 无限递归调用图 | 成本高且大量内容与任务无关 | 默认直接关系，只沿影响判断的一条关键链继续 |
| 把搜索未命中当作不存在 | 动态注册和外部消费者可能不可见 | 标为 `partial` 或 `unresolved`，说明搜索边界 |
| 自动沉淀所有发现 | 易变实现污染长期知识 | 动态切片留在当前 Spec，只有稳定且获批内容进入 Knowledge |
| 把文档描述当作代码事实 | 文档可能过期 | 对照当前实现、Schema、测试和 revision，保留冲突 |
| 没有版本仍称完整 | 后续无法复核 | 记录 revision；不可用时写明快照边界并降级为 `partial` |
| 为 Bootstrap 扫描整个仓库 | 接入成本失控，敏感内容暴露面增加 | 从目标路径和入口开始，满足当前接入目标后停止 |
