# 工作流与边界

## 证据优先级

按当前任务选择最窄、最直接的来源：

1. 项目规则和当前 Active Spec 定义允许范围与不可变目标；
2. 公开 Schema、类型、模块出口和契约测试支持稳定边界；
3. 实现、调用方和邻近测试支持当前版本的动态切片；
4. 文档、注释和历史说明用于解释原因，但与代码冲突时必须显式报告；
5. Agent 推断只能作为 `inferred` 或 `unresolved`，不能提升证据等级。

## 最小 Bootstrap

优先回答五个问题：

1. 这个项目或模块从哪里进入？
2. 哪些规则决定允许和禁止的修改？
3. 哪些契约一旦猜错会导致实现错误？
4. 哪些代码入口和测试可用于后续任务定位？
5. 哪些事实仍有冲突或缺少负责人批准？

能回答当前接入目标后停止。除非用户要求完整治理审计，否则不扩展到无关模块。

## Section Index 消费规则

Section Index 是确定性导航，不是语义摘要：

- 必须等待 Resolver 返回后再安排 Active Spec 正文检索；不要把 Resolver 与对 Spec 目录的广泛搜索并行执行；
- 对 `sectioned` 事项，先从索引选择章节，再使用行区间或等价的局部读取展开；选定前从广泛 `rg` 和全文读取中排除其核心文档；
- 先按标题、规则编号和未完成 Checklist 定位候选章节；
- 读取相关章节原文后才能提取约束；
- 任务改变产品行为时优先看目标、完成条件、非目标和业务规则；
- 改变技术路径时优先看 Plan 的组件、数据流、关键决策、兼容和风险；
- 继续实施时优先看未完成 Tasks，并回读其引用的 AC/Plan；
- 标题不足以判断相关性时将该章节列为未确认，不猜测正文。

## 动态切片扩展顺序

```text
任务目标
→ entrypoint / symbol / data_element
→ 真实定义
→ 直接调用与直接消费者
→ 一条关键数据链
→ 契约、异常、兼容和测试
→ 停止或带理由继续深入
```

默认不递归遍历所有依赖。以下情况允许继续深入一层或沿关键链继续：

- 当前层只是转发，真实行为仍未出现；
- 数据在下游发生影响验收的转换；
- 异常、权限、缓存或兼容行为由更深层决定；
- 测试证明消费者位于间接边界。

每次继续深入都应能回答一个当前任务问题；否则停止。

## 持久化边界

| 内容 | 建议位置 | 条件 |
| --- | --- | --- |
| 仓库工作边界和禁止事项 | 根级或模块级规则 | 维护者确认，且跨任务稳定 |
| API、Schema、不变量和兼容边界 | Knowledge | 有权威来源、刷新条件和维护者批准 |
| 当前任务调用链、数据链和消费者 | Spec Research / Evidence | 绑定候选版本和 Evidence |
| 精简方案引用 | Spec Plan | 只保留影响决策的结论与详细切片链接 |
| 证据冲突或缺失 | 当前报告或 Spec 未决问题 | 未解决前不得提升为稳定事实 |

## 新鲜度

以下变化使切片失效或需要复核：

- 候选 revision 改变且命中切片路径；
- 入口、导出、Schema、类型或契约测试变化；
- 直接消费者、异常分支或兼容路径变化；
- Active Spec 的范围或完成条件变化；
- 依赖 Knowledge 进入 `review-required` 或被取代。
